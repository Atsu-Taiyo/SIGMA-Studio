# Design Rules

Sigma Studio の画面ごとの配置と、編集操作の決まりを書く。色・文字・余白・角丸・共通部品のように、どの画面にも共通する見た目は [DESIGN.md](../DESIGN.md) に書き、ここでは扱わない。

製品の実際の挙動とこの文書が食い違ったら、挙動に合わせてこの文書を直す。仕様を変えるときは、同じ変更の中でこの文書も更新する。

## Editor Screen

編集画面は、教材の本文を中心に置く。中央の編集領域を最も強く、補助パネルは薄い背景、細い境界線、小さな文字で控えめに見せる。

```text
クローム: タイトル行・メニュー・文書タブ・ツールバー (Word風はリボン)
ポケット (使うときだけ)
本文キャンバス (左上: AIタスクとアウトラインの入口 / 右上: サイドバーの内容とコメントのカード)
ステータスバー (Word風だけ)
右サイドバー (上の並びの右に、ウィンドウの上端から下端まで)
```

### Right Sidebar

- 右サイドバー (ファイル・ブラウザ・サイドチャット) は、タイトル・メニュー・本文・ステータスバーの縦の並びの右に、ウィンドウの最上端から最下端まで全高で並べる。タイトル行の下から始めない。開く入口はタイトル行の右端のアイコンボタンで、開いている間はサイドバー自身の閉じるボタンが同じ位置に来る。本文の列が狭くなったら (幅 820px が境目)、タイトル行の補助アクションは文字を省いてアイコンだけにする
- サイドバーの中はタブで分ける。「+」を押すと Hub (ツールとおすすめのサイト) が開き、選ぶと Hub がその面に置き換わる。右上の × はタブを残したままサイドバーを畳み、最後のタブを閉じるとサイドバーごと閉じる
- 幅は既定で 400px。320〜720px の範囲で、ウィンドウの幅の 60% までに収める。境目のハンドルをダブルクリックすると既定の幅に戻る
- 右サイドバーを閉じていて、中にウェブのページが開いているときは、キャンバスの右上に小さなカードで中身 (ページ名とアイコン) を見せる。選ぶとそのページでサイドバーを開き、「すべて表示」で最後に見ていたページを開く。カードは閉じられ、ウェブのページの顔ぶれが変わると再び出る
- このカードにはファイルとチャットの行も出る。ウェブのページは4件まで並べ、置く幅が足りないときは地球儀のアイコンと件数だけにする

### Comments

- コメントは、デスクトップ版では本文の右横の欄ではなく、キャンバスの右上に浮かぶカードの縦並びで見せる
  - 通常の教材もホワイトボードも同じ並びで、開いた状態から始まる (ホワイトボード専用のコメントボタンは置かない)
  - サイドバーの内容のカードがあればその下に積み、サイドバーを開くとその左へ避ける
  - カードは本文の上から下の並びに揃え、本文をスクロールしたら見えている対象のカードへ追従する
  - 対象の本文側は、既存の参照先の色で示し、カードから本文へ線や矢印は引かない
  - 2人以上が発言したスレッドは見出しに発言者を重ね、3人目から薄れさせて4人目以降は「+N」にする
- 用紙の右にカードを置く余白が足りないとき (窓が狭い・サイドバーを開いた・拡大した) は、右のカードたち (サイドバーの内容とコメント) を小さな丸いアイコンだけにする。コメントのアイコンを押すとその場でカードに広がり、外側を押す・Esc でアイコンへ戻る。書きかけのコメントは広げたままにする
- アイコンにする境目は、幅 300px のカードの並びが用紙へ 48px を超えて掛かるとき (用紙の右の余白には文字が無いので、そこまでは入り込んでよい)。ホワイトボードは用紙が無いので、本文の窓が 980px より狭いとき
- 自分宛ての未解決のメンションがあるときは、コメントを隠していても「@N」のボタンを出す。アイコンは6件まで並べ、残りは「+N」にまとめる
- コメントの入力欄 (新しいコメント・返信・編集) は Figma・Claude のコメントと同じ形にする
  - 枠の中に本文を書き、下の段の右端の丸いボタン (矢印、編集はチェック) で送る
  - Enter で送り、Shift+Enter で改行する (変換確定の Enter とメンション候補を選ぶ Enter では送らない)
  - AI へは本文に `@claude` などと書いて頼む
  - 「Claude に送信」のような切り替えと、`@` だけのボタンは置かない
  - `@` を打ったときの宛先の候補は入力欄の中に差し込まず、キャレットの下に浮かべ、メンバーと AI Agent を分けて並べる
  - 浮かべた入力欄の左には書き手のピン (左下がとがった涙形のアイコン) を置き、時刻は「今」「5分前」のように経過で書く (正確な日時はツールチップ)
  - アイコンの画像が読めないときは灰色の丸にせず頭文字 (英字の姓名は2文字) に戻す
  - カードには「ブロック」「図形」「選択した領域」のような付け先の種別を出さない (本文のハイライトや図を見れば分かる)
  - 出すのは本文を見ても分からない「対象なし」と「解決済み」だけ
  - 本文や数式の引用は中身なので残す
  - 引用元とコメントの本文は、本文と同じ静的な描画 (`InlineContent`) で書式・数式のまま出し、入力欄も本文と同じ共通エディタエンジン (`createRichTextEngineExtensions`) で組む (コメント専用の描画や拡張の組み合わせを作らない)
- コメントは ⌘/Ctrl+Enter でも送れる。浮かべた入力欄で Esc を押すと、空なら取り消し、書きかけなら右上のカードへ移す。時刻は1週間を過ぎると日付で書く

### Selection Card

本文・画像・図形を選ぶと、選んだところの近くに操作のカードを1枚出す。操作を別々のチップに分けない。

- 本文を選んだときのカードは幅 288px で、書式を2段に分ける。1段目は太字・斜体・下線・囲み文字・文字色・ハイライト、2段目は書体・サイズ・揃え・その他のブロック。区切り線の下に「ポケットに追加」「AIに依頼」とコメントを並べる
- 段落スタイル (本文・見出し) の切り替えは上部ツールバーに任せ、カードには置かない
- 「ポケットに追加」と「AIに依頼」には言葉を添える。コメントはアイコンだけにして右端に置き、名前は「コメントを追加」とする
- 本文の選択では、カードを選んだ文の下に出す (上に出すと前の行を隠す)。画面の下に収まらないときだけ上へ回す
- 数式だけを選んだときも同じ書式のカードを出す。このときはカードを上に置く
- 図形の選択では、図形の上下ではなく選んだ (動かした) ときのマウスの右下に出す (拡大していると図形の上下は画面の外にあり、カードが見えなくなる)。右・下に収まらなければ左・上へ回す。キーボードで選んだときはマウスの位置が無いので図形の上に出す
- 図形のカードは段を決め打ちせず、操作を左から並べて幅に収まらなければ折り返す。「…」(その他) は右上に置く。区切りは線ではなく少しの間にする (折り返しで行末に線だけが残らない)
- 本文の選択から開く AI の入力欄とコメントの入力欄は、カードの下ではなく選んだところのすぐ下 (選択が終わった位置の下。2段組で段をまたぐときも、いちばん下の行ではなく選択が終わった段) に開き、選んだ文を隠さない
- 本文から始めたコメントは右上のカードの並びではなくその場で書き、外側を押したら書きかけのまま右上のカードへ移す
- つまみで画像や表などのブロックを丸ごと選んだときは書式のカードを出さず、「AIに依頼」「コメント」を選んだところの右下に小さなチップで出す。チップは用紙の右端を越えるなら右端に揃え、用紙・画面の下に収まらないときだけ選択の上へ回す
- 本文にカーソルを置いただけのときは何も選んでいないので、カードもチップも出さない (常に画面に浮かべない)
- ポケットのカードをドラッグしている間は、落とし先の本文を覆わないようカードを隠す

### Account Profile

- 名前とアイコンは、アカウントのメニューの「名前とアイコンを変更」から自分で変えられる (アプリ内のダイアログ。画像は選んだ範囲を 256px 四方に縮めて送る)
  - 保存先は共有サーバーで、見られるのは本人と教材・フォルダを共有している相手だけ
  - 名前を空にすると Google の名前に、「Google のアイコンに戻す」で Google のアイコンに戻る (Google のアイコンが無い人には「アイコンを外す」を出す)
  - コメントは書いた人の共有アカウントの ID を持ち、表示のときに今の名前とアイコンで描く (変えたら過去のコメントにも出る)
  - 引けない人は保存してある名前と頭文字で描く
- アイコンの画像を選んだら、送る前に「アイコンの範囲」を名前とアイコンのダイアログの上に重ねて開き、どこをアイコンにするかを選ばせる
  - 初めは真ん中の正方形 (短い辺いっぱい) で、ドラッグ・矢印キーで位置を、拡大率のスライダー・ホイール・ピンチ・+/- で大きさを変える (縦横比は変えない。範囲は画像の外に出さず、短い辺より広げない)
  - 丸い枠の中が実際のアイコンで、外側は暗くして画像の続きを見せ、下に表示する大きさ (64px・28px) の見本を並べる
  - 「適用」で範囲を 256px に縮めた見本に替え、キャンセル・Esc ではそれまでのアイコンのまま
  - 適用した後は「範囲を調整」で、選び直さずに前の範囲から調整し直せる

### Status, Tabs And Panes

- 右上の状態表示には、エラーと警告だけを出す。「保存しました」「教材を開きました」のような成功・経過の報告は画面に出さない（読み上げ用の非表示領域には残す）。保存中・未保存はタブの点で示す
- タブを並べて分割したとき、見えているペインはどれも編集面のまま並べる。読み取り専用の描画や印刷プレビューへ切り替えない。押したペインが編集対象になり、教材を読み直さない

### Sharing, Plans And History

- 共有は教材ごとの操作として、タイトル行の「過去の版」の左に置く。ヘッダーで塗りつぶしのボタンは「共有」だけにする
- プランで許されない操作は、その操作をした時点でPaywall (`CollaborationPlanDialog`) を開き、見出しに止めた理由を書く。操作前にPro限定の案内文を常設しない
  - 共有ダイアログの「管理者」のように選んだ時点で Paywall が開く選択肢には、選ぶ前から小さな Pro バッジを付ける
  - 設定の「アカウントで同期する（Pro）」は、Pro でないときスイッチを無効にし、説明文に Pro の機能であることを書く
- 「過去の版」を開いたら、右サイドバーを閉じてコメントを隠す。版をプレビューしている間は、クロームを `inert` にして操作できなくする。版の一覧は点を線でつないだタイムラインで並べ、選んだ行は薄いグレーの面で示す

### Pocket

- ポケット (クロームと紙面の間の一時置き場) は、使うまで画面に出さない
  - 入れると開き、畳むと高さ0になり (紙面を押し下げない)、アイコンと「ポケット N件」を並べた小さな丸いチップ (バーの帯や枠は出さない) を上部の真ん中に重ねて出し続ける (ホバーを待たない)
  - 空に戻ると消える
  - 上部の真ん中にほかのチップ (表示の絞り込み) が出ているときは、重ねずに真ん中の線を挟んで横に並べる
  - 開閉は、バーが上から伸び縮みし、紙面が同じ速さで押し下げられ・引き上げられる
  - 閉じるときは畳み終わるまで中身を描き続けて、押せなくする
  - 入れたときは、選んでいた部分がカードへ飛んでいく (閉じていたなら、開き切ってから)
  - 動きは、動きを減らす設定では出さない (一瞬で切り替える)
  - カードは中身そのものを小さく見せ (本文は紙面と同じ描画、図形は図そのもの)、種類は隅の小さな目印だけで示す
  - カードは押すとキャレットの位置へ、ドラッグすると落とした場所へ入る (ドラッグ中はポインタに付くゴーストで運んでいることを示し、受けない場所では薄くする)
  - ホワイトボードのように本文の無い紙面では、本文のコピー (問題を含む) も文章の図形として置く
  - 問題はテキスト部分だけで、番号・枠・タグは付かない
  - ポケットを使わない貼り付けも同じ
  - 選択のカードの「ポケットに追加」は、アイコンだけにせず「AIに依頼」と同じく言葉を添える
  - 外す操作はホバー・フォーカスで出し、外した直後は同じ場所に「元に戻す」を添える
  - うまくいかなかった理由は、押しても何も起きない状態にせず、ポケットの中に言葉で出す
  - ポケットは教材ではなく作業台なので、保存・共有・履歴に載せず、共有していても相手には見せない
- 入れられるのは30件まで。開いたバーの高さは 88px、開閉は 280ms。外したあとの「元に戻す」は8秒、うまくいかなかった理由は5秒出す

### Component Settings

- 教材要素の詳細設定を常設サイドバーへ出さない。問題、box、コードブロックなどコンポーネント単位の設定は、対象のホバー時に右上へ出る3点ボタンから開く
- 3点ボタンは、その要素の操作メニューを開く。box は「タイトルを編集…」「boxの設定…」「コピー」「削除」、問題は「問題の設定…」を含む「問題操作」。設定ダイアログはこのメニューから開く
- コードブロックの言語と背景 (ライト / ダーク) は、ダイアログではなく小さなポップオーバーで変える。全体ツールバーへ常設しない

## Editor Chrome Layouts

編集画面のクローム（メニューバーとコマンド面）は2系統ある。どちらを使うかはユーザーが選ぶ設定で、初回起動時に1画面で選ばせる。

- 既定は**Googleドキュメント風**（1段のツールバー）。迷ったらこちらに寄せる。
- もう一方は**Word風**（タブで切り替えるリボン）。Wordのブランドカラー（青）は使わず、面と線は無彩色パレットに収める。選択中・フォーカス中・押下中などの**状態表現に既存のアクセントを使うのは従来どおり可**。
- 選択中のタブは濃い枠線で囲まず、**薄いグレーの面**で示す（[DESIGN.md](../DESIGN.md) の Selection に従う）。
- リボンのグループ見出しは 11px / `--text-muted` (幅 1120px 以下では 10px)。コマンドそのものより弱く置く。グループ間の区切りは影ではなく 1px の縦罫。
- クロームの高さは `--editor-chrome-height`・`--editor-pocket-height`・`--editor-statusbar-height` のトークンで管理する。本文キャンバスの `calc(100vh - …)` に生のpxを書かず、3つとも引く（レイアウトごとに行数が違うため、数値を散らすと必ず片方だけずれる）。docsでは `--editor-statusbar-height`、ポケットを閉じているときは `--editor-pocket-height` が `0px` なので、同じ式のまま見た目は変わらない。
- コンテキストタブ（図形の書式など）は**対象を選択したときだけ**出す。ツールを構えただけでは出さない（中身が全部disabledのタブへ飛ばされる）。選択を解除したら、直前にユーザーが自分で選んだタブへ戻す。
- 本文ブロックのうち箇条書きと番号付きリストはツールバーへ直接置き、引用、コードブロック、区切り線、囲み枠は「その他のブロック」メニューへまとめる。
- 番号付きリストのボタンは、`1.` `(1)` `(a)` `(i)` の4つの書式を選ぶメニューを開く。
- 左端のアイコンは「ワークスペース」という名前のボタンで、教材一覧を開く。教材一覧のロゴと同じ位置に置く。
- ページの並び (1列 / 2列の見開き) は表示の設定で、教材には保存しない。Word風は表示タブの専用グループ、docs は切り替えのボタン1つで選ぶ。
- レイアウトを選ぶ初回の画面は、デスクトップ版でだけ出す。カードを押すとそのレイアウトを適用して閉じ、確定のボタンは置かない。× と Esc は今のレイアウトのまま閉じる。

Word風は Word 365 の画面構成に倣う。色と余白は [DESIGN.md](../DESIGN.md) の無彩色パレット・`--space-*` のまま。

- **ファイルタブは Backstage**（編集画面を覆う1画面）にする。左に縦のナビ（← 戻る / ホーム / 新規 / 開く / 情報 / エクスポート / オプション / ヘルプ）、右に選択中セクションの内容。**Backstageのコマンドには必ず文字ラベルを付ける**（アイコンのみに落とすと動線が読めなくなる。これがWord風初版の実際の失敗）。Esc / ← / ファイルタブ再クリック / 他のタブのクリックで閉じ、**コマンドを押したら必ず閉じる**（本アプリのダイアログは背面を `inert` で隔離するので、開いたままだと閉じた先に忘れられた全画面が残る）。
- **タイトル行は 左端アイコン → クイックアクセスツールバー（保存状態・元に戻す・やり直す）→ 中央に教材タイトル → 右端の常設アクション**。タイトルを「残りの領域の中央」ではなく**行の中央**に置く（左右の列を同じ幅にする）。undo/redoはホームタブに置かない（Word 365 2023+ と同じ）。
- **リボン本体は2段構成**。グループの左に大ボタン（アイコンの下にラベル）、右に小ボタンを2段に積む。ダイアログランチャー（↘）は**対応するダイアログが実在するグループにだけ**付ける（押しても何も起きないボタンを作らない）。同名の大ボタンと衝突しないよう、ランチャーのアクセシブル名は「…ダイアログを開く」にする。
- **リボンは折りたためる**。折りたたむとタブ行だけになり、タブを押すと本体が一時的に浮いて出る（本文は動かさない = 高さトークンを変えない）。閉じるのは 外側クリック / Esc / 同じタブの再クリック / 展開ボタン / タブのダブルクリック / Ctrl+F1。畳んだ状態は次回起動時も保つ。
- **ステータスバーは画面下端**に置き、左に「ページ N / M」、右にズーム。ズームは表示タブにも残す（Wordも両方に持つ）。読み上げが鳴り続けるので `role="status"` にはしない。
- 同じコマンドが複数の面に出ることは受容する（ワークスペース、コメント表示、ズームなど。Word自身がそう）。ただし**同時に可視にはしない**（Backstage表示中はタイトル行・タブ行・ステータスバーのコマンドを消す）。見えていない本文へコマンドが効く状態を作らないこと。
- **新しいコマンドを追加するときは、両レイアウトでの置き場所を決めてから実装する。** 片方だけに足すと、もう一方のレイアウトでは到達不能なコマンドになる。これは規約であると同時に**機械的に担保されている** — `apps/desktop/tests/e2e/ui-layout-parity.spec.ts` が両レイアウトのコマンド集合を双方向で突き合わせ、片側にしか無いコマンドがあれば落ちる。意図的な差分は理由付きの許容リストに載せる（実体の無くなったエントリも検出される）。
- 段組み (2・3・4段組と解除) は Word風のレイアウトタブにだけ置き、docs ではキャンバスの右クリックから行う。この差は上のテストの許容リストに載せている。

### Extensions Menu

拡張機能が足すメニューは、メニューバーの一番右の「拡張機能」に出し、既存のメニューには混ぜない。Word風では Backstage の「オプション」に同じ内容を出す。

- 中身は拡張機能が決めるが、描くのはアプリの部品だけ (拡張機能名の見出し・区切りの見出し・説明文・ボタン・区切り線)。ボタンのアイコンはアプリが持つ固定の集合から選ばせ、任意の画像や HTML は描かない
- 拡張機能名の見出しは常に出す。メニューの中身が、アプリ自身の項目に見えないようにする
- 内容が無い (拡張機能が無い・権限が外れた) ときは、メニュー自体を出さない。入れ方と管理の入口は、メニューの末尾の「拡張機能を管理…」と、設定の「拡張機能」に置く
- 長い文字列はメニューの幅に収まるよう折り返し、項目が多いときは高さに上限を置いてメニュー内でスクロールさせる

## Workspace Home

- 同じワークスペース・フォルダ内で教材を新規作成・複製・改名するとき、同名なら「教材名-2」「教材名-3」とハイフン付きの連番を付ける。複製は「教材名 のコピー」とする。編集画面の改名は確定時に保存し、一覧へ戻る前に保存中の処理と未保存変更を反映する。
- 新規の無題教材を何も編集せずタブの×で閉じたら、教材自体も一覧から除く。名前変更・入力・書式変更をした教材は残す。最後の空タブを閉じた場合はワークスペースへ戻る。
- 編集画面の「新規教材」は、押すと直前まで開いていた教材と同じワークスペース (同じフォルダ) に作る。ホバー (キーボードでは↓) で開くメニューの下段に、作れるワークスペースを「…に作成」と並べ、押したときの作成先に ✓ を付ける (Word風は Backstage の「新規」に同じ項目)。直前の教材の場所に作れない (閲覧だけの共有など) ときは、このPCの既定の作成先に作る。何でもクラウドに作ることはしない。作ったら、ワークスペース名・フォルダの階層 (直下ならその旨)・保存先 (このPC / クラウド) をダイアログで示す。

教材一覧画面（`/workspace`）は、Google Driveのようなファイルブラウザの構成にする。

```text
header: ロゴと「Sigma Studio」 / 中央のピル形の検索 / 参加・テンプレート・編集画面に戻る・アカウント
left sidebar: 開閉ボタンと「新規」 / コメント・ブックマーク / ワークスペース一覧 (アイコン列へ畳める)
content: 多階層パンくず / フォルダと教材の一覧 (表)
```

- ヘッダーの「参加」は共有機能が使えるときだけ、「編集画面に戻る」は編集画面で教材を開いているときだけ、「再試行」は読み込みに失敗したときとオフラインのときだけ出す。保存の状態はヘッダーに出さない
- 一覧はリスト表示だけにする。グリッド（カード）表示と教材のサムネイル画像は持たない (表示の切り替えも置かない)。一覧を出すために教材の本文を読んだり、ページを組んだりしない
- 一覧は「名前」「更新日時」「場所」の列を持つ表にする。「名前」と「更新日時」の見出しを押すと並び替え、もう一度押すと昇順・降順を反転する (「場所」では並び替えない)。既定は更新日時の新しい順。並び替え中の列にだけ、アクセント色の丸い矢印を出す。並び順は保存して次回起動時も維持する。並び順に関わらずフォルダは常に教材より上に表示する
- クリックは選択、ダブルクリックで開く（Google Driveと同じ挙動）。設定やメタ情報のパネルは常設しない
- 一覧では Enter / Space で開き、F2 で名前を変え、Delete / Backspace で削除する。左サイドバーのツリーでは、教材を1回押すと開く
- 編集画面のタブで開いている教材の行には「編集中」のバッジを付ける
- 左サイドバーは「新規」の下に「コメント」「ブックマーク」を置く (「コメント」は共有機能が使える環境でだけ出す)。押すと本体が、全ワークスペースを横断するその一覧へ切り替わり、ワークスペースやフォルダ、検索を操作すると教材一覧へ戻る。「コメント」のバッジは自分宛ての未解決スレッド数 (`@件数`) だけを数え、自分が書いたコメントの数は数えない。コメント一覧の項目はその教材の該当スレッドへ直接開く
- 左サイドバーは、サイドバーの上端で「新規」の左にあるボタンで開閉する。畳んだ状態は、ワークスペースの一覧とツリーを隠した64pxのアイコン列で、開閉ボタン・「新規」・「コメント」(バッジ付き)・「ブックマーク」を縦に残す。開閉は次回起動時も保つ
- 「新規」は、新しいフォルダ・新しい教材・新しいワークスペースを選ぶメニューを開き、続けて名前を決めるダイアログを開く。教材のダイアログのボタンは「取消」「作成のみ」「作成して開く」で、Enter は作成して開く。「作成のみ」は検索を解除してそのフォルダへ移り、作った行を選んで見える位置へ送る
- ブックマークは行のボタンとメニュー項目で付け外しする。付けた項目はボタンを常に見せ (状態をホバーなしで読める)、付けていない項目はホバー・フォーカスで現れる。ブックマークはこの端末の設定で、教材ファイルや共有には書かない
- 名前変更はダイアログを開かず、行の名前をその場でインライン編集する
- パンくずは現在のフォルダまでの階層をすべて表示し、途中の階層をクリックすればそこへ戻れる
- フォルダも教材と同じ表の行で表現し、行の操作ボタンはホバー時のみ表示する。フォルダを開いている間は、パンくずの右に「フォルダを移動」「フォルダを削除」のアイコンボタンを常に出す
- ワークスペースの削除は確認ダイアログに含まれる教材・フォルダの件数を明示し、最後の1つは削除できない
- 検索は全ワークスペースを対象にする (プレースホルダーは「すべてのワークスペースを検索」)。題名に一致した教材の後に、本文に一致した教材を抜粋付きで並べ、パンくずは「ワークスペース名 › 検索結果」にする
- 保存・エラーなどの状態は左下のトーストで伝える。成功は約2.6秒で消し、エラーは次の操作まで残す
- アプリ内のマニュアルは持たない。使い方は、しばらく操作が無いときに出す「使い方を見てみませんか？」のダイアログから、外部の操作マニュアルへ案内する。「もう表示しない」を選んだら以後は出さない

## AI Agent Activity

サイドバーのAIエージェント実行表示は、Codex CLIのような1行のステータス表示を基本にする。

- 実行中は処理内容に対応するモノクロのThinking OrbとテキストShimmerで現在の処理を1行で示し、経過時間を添える。Orbは実行中の状態表示に限定し、完了後や静的な装飾には使わない
- 本文キャンバス上の実行アンカーと図形ロックOverlayは、処理状態のOrbではなく実行元を識別できる各AIプロバイダのロゴを使う
- 詳細ログ（推論・プラン・イベント）は折りたたみ、求められたときだけ展開する
- 枠線や背景色のついたチップにせず、テキスト中心の控えめな表現にする
- 内蔵の SIGMA AI は Σ の印で表す。実行アンカーのロゴは実行中に Shimmer で明滅させ、終わったら ✓ か × を添える
- Orb は、会話の一覧とAIタスクの入口の実行中の表示にも使う
- 生成した画像があるときは、詳細ログを初めから開いておく

## Editor Specific Rules

### Text

- 教材中の文字サイズは1ptから選択でき、1pt以上の数値（小数も含む）を直接入力できるようにする。選択範囲への適用と保存後のサイズを保つ
- 行の高さは、その行に含まれる文字サイズ・数式と段落の行間倍率から決める。小さい文字だけの行に標準本文サイズの最低高さを残さず、同じ段落でも折り返した各行に必要な高さを確保する。段落下余白・見出し前後の余白・フッター領域の高さは別に扱う
- 本文編集では段落末尾・明示的な行内改行ともに `↵` を表示する。空の教材でプレースホルダーが出ている段落には出さない。編集記号は本文の寸法を変えず、保存・コピー・印刷には含めない

### Math

数式編集は、見た目の美しさと入力のしやすさを両立する。

- 数式は `mathInline` として扱い、`\\` を含むTeXも本文行の高さを優先して表示する
- 短い数式は本文行のリズムを崩さない
- 編集中の数式はフォーカス状態を明確にする
- TeX入力欄は必要な時だけ表示する
- 数式エラーは派手にせず、該当箇所の近くに控えめに出す
- 教材タイトルの `$…$` は表示面でのみ数式として描画する。保存値は入力どおりの文字列で、描画のためにデータを書き換えない
- 対になっていない `$`・散文 (`セール $100 と $200`)・元の文字列を復元できない書き方 (`$ x^2 $` や `$$…$$`) は数式にせず、タイトル全体を素の文字列として表示する。`$` を記号として使いたい場合は、対にならないよう 1 つだけ書けばそのまま表示される
- タイトルはツールチップ・`aria-label`・ファイル名・検索など素のテキストしか置けない面では生の文字列のままにする
- 数式の markup は `renderMathHtml` (`features/rendering/adapters/math-html.ts`) の出口で許可リスト方式に無害化する。TeX から HTML を作って `dangerouslySetInnerHTML` へ流す経路をここ以外に作らない
- 数式の一部だけフォントを変えるときは、数式の入力欄 (TeX モードではない方) で範囲を選び、ツールバーのフォントを選ぶ。TeX には `\htmlStyle{font-family:…}{…}` として残り、選んだ範囲の文字・数字・`\text` だけがそのフォントになる。大きさで字形を選ぶ記号 (積分・括弧・根号) と `\mathbb` などの書体命令は変えない。個別に選んだフォントは、本文や段落のフォントより優先する
- 危険な文字 (`<` `>` `&`) を含む TeX を数式にしない、という入口フィルタは足さない。これらはごく普通の数学 (`$a<b$`、`\begin{aligned}…&…\end{aligned}`) で出るので、防御ではなく機能破壊になる

### Shapes And Images

図解、グラフ、画像（いずれもオーバーレイのシェイプ）は教材の一部として扱う。

- 選択中だけリサイズハンドルや整列ガイドを表示する
- 小さい図形ではリサイズハンドルを描かず、図形そのものを見せる。短辺が紙面で 40px 未満なら辺の持ち手を、24px 未満なら角の持ち手も描かない (点ハンドルも 24px 未満で消える)。描かない持ち手もその場で掴め、カーソルで示す。何も描かない大きさでは掴む範囲を枠のすぐ外側へ出し、図形の内側は移動に残す
- 図形モードで図形を掴めるのは「描かれているところ」だけにする。図形のDOMは外接矩形（変形の基準箱）だが、それを当たり判定にはしない。円弧は元の円まるごとが基準箱なので、弧の内側の空白は空白として扱う
- 図形内の文字・吹き出し・表セルの編集中は、上部ツールバーの文字書式をその編集対象へ適用する。サイズ入力などへフォーカスが移っても選択範囲を維持し、文字図形全体の選択と文字の範囲選択を区別する
- 図形・表の貼り付けは、図形と画像資産をSigmaDocへ同じ操作で確定してから選択を移す。Cmd/Ctrlを離す、一時的な図形モードを抜ける、教材を再表示する操作で貼り付け結果が消えないようにする
- 図形を貼り付けるとき、ポインタが編集面の上にあればその位置に置く
- TIF / TIFF の画像は、取り込むときに PNG へ変換する
- 図や画像の境界線は薄くする
- 空の図形ブロックはアイコン中心のプレースホルダーにする

### Body Selection

- 図形モード中でも、図形の外側で本文に触れたら本文へ戻す。クリックはその位置のキャレット、図形を1つも囲まなかったドラッグはその範囲の文字選択として引き継ぐ。紙の余白（本文が無いところ）での空振りマーキーは図形モードに留まる
- 本文のドラッグ選択は、左右の余白へ出ても近い行の端へ伸ばす。余白から選び始めた場合は本文へ入った行を起点にし、開始位置まで戻せば選択を畳む。内部の編集面の分割によって操作結果を変えず、ドラッグ中の表示・離した後の選択・次の入力の置換範囲を一致させる
- 通常の左ボタンを押したまま本文上を動かす操作は、キャレットや既存の選択がある場合も本文の範囲選択として扱う。連続クリックの後も追跡を続ける。Cmd/Ctrlによる図形操作、専用のブロックグリップ、入力欄・ボタン・数式の編集操作は各操作の経路を保つ

### Body Anchors

- 本文アンカーは錨アイコンではなく、「ここから下がこの図」と読める境界線として表示する。線は紐付く本文行の**直後**（最終行はブロック下端）に引き、段落の途中を横切らせない。両端の爪は図のある側 (通常は下、図が線より上にあるときは上) へ向け、図までは破線の引き出し線でつなぐ
- 選択中の図形には、本文アンカーのグリップをアイコンだけで表示する (グループのメンバーとグラフのラベルには出さない)。境界線、図までの引き出し線、接続先本文の面表示はグリップのホバー・フォーカス・ドラッグ中だけ表示する。接続状態の説明もグリップのホバー・キーボードフォーカス時だけツールチップで表示し、常設しない
- アンカー線そのものは `pointer-events: none` にし、掴めるのは中央のグリップだけにする（本文のクリックを線が食わないようにする）
- アンカーのドラッグはブロック単位でスナップし、ドラッグ中は紐付け先の本文ブロックを面で示す。本文に繋がっていない図形 (「本文と繋がっていません」) と、別の図形に繋がっている図形は灰色の破線で、接続先の本文が見つからない図形は琥珀色の破線で区別する
- アンカーUIは絶対配置で、本文の高さや改ページを変えない
- ページに固定されていて本文に繋がっていない図は、教材を開いたときに同じ高さの本文へ一度だけ接続する

### Block Grip And Drag

本文ブロックの操作は、左ガターのグリップ (⋮⋮) 1つに集める。

- グリップはホバー中の1単位だけに出す。選択しただけでは出さず、選択は枠で示す
- グリップを押すと、その単位を選択して右クリックと同じメニューが開く。メニューには段組化と段組の変更・解除、box の操作、素材に追加、改ページ・改段の挿入と解除、削除を置く
- 複製・上下移動・ブロック種別の変更のための専用ボタンは置かない。移動はドラッグと ⌥⇧↑/↓ で行う
- 本文のブロックグリップ（左ガターの ⋮⋮）は「掴んで動かす」もの。押して数 px 動いたらドラッグ、動かさず離したらクリック（選択とメニュー）。グリップは掴む単位ごとに出す — 箱・引用・段組・問題エリアの中の段落、リストは 1 項目ずつ（Enter で分かれた項目が別ブロック、Shift+Enter の継続行は同じ項目）。左ガター・段間でもポインタが居るレーンと高さの最も内側の単位へ出し、問題・箱・段組そのものは最初の行より上の上端帯からだけ掴める
- ページを跨ぐブロックは同じSigmaDocのIDを保ち、各ページで見えている範囲にグリップ・選択枠・ドロップ判定を対応させる。元ページで隠れた部分やページ間の空白を選択枠で覆わない。下余白つまみは本文の実際の末尾にだけ出し、続きの表示枠の端を文書の挿入境界として扱わない
- 本文を足す ＋（挿入線）は、文書の先頭ブロックの上と、問題・箱・コード・引用の前後に加えて、問題の各領域（導入文・問題文・コメント・解答）の末尾にも同じ見た目で出し、押すとその領域の中の末尾へ空の段落を足す（最後が空の段落ならそこへ入る）。末尾はページ・段を跨いだ最後の断片の実際の下端だけで、隣の段の同じ高さには出さない。問題の外の辺のすぐ内側で終わる領域（最後の領域）は、外の辺の ＋（問題の前後に足す）に任せる
- ブロックのドラッグ中は本文を 1px も動かさない。掴んだ単位の写し（ゴースト）がポインタに追従し、元のブロックは紙色のベールで薄くし、落とし先は線で示す — 前後なら横線、横並び（段組化・段の追加）なら縦線。線は挿入線と同じアクセント色で、端に丸を付ける。Esc でキャンセル、文書へ書くのは離した 1 回だけ（undo も 1 手）
- 落とし先はブロックの左右端の帯（幅の 18%、20〜56px）で横並びになる。問題・段組そのものは横並びにできず、その帯でも前後の横線に倒す。段組の段は最大 4。空いた段は詰め、1 段になった段組は解く
- グリップと下余白線は、部分段組を含め常にホバー中の 1 単位だけへ表示する
  - 文字そのものではなく、左ガター・段間を含むそのレーンの行高に入れば操作できる
  - 外側の段を先に解決してからその段の入れ子だけへ降り、兄弟段の同じ高さにある入れ子へ飛ばない
  - 入れ子リストの行から左へ移動するときは各インデント帯でも最深の項目を保ち、親項目へ跳ばない
  - リスト項目のグリップと下余白線はマーカー（•・○・番号・(a)・(i) など）の左、つまり項目が属するリスト要素の左端を基準に出し、マーカーに重ねない
  - 親項目の下余白線は親の本文行の下（入れ子リストの手前）に出し、リスト全体の下には出さない
  - 段の左ガターはその段へ帰属する
  - 部分段組の段間は列境界（幅の調整）が持ち、2段目以降のグリップと下余白線は段の本文に寄せて段間の右半分に収め、列境界の中央線を覆わない
  - 段の行から段間へ出ても、その行の高さにいる間はグリップと下余白線を保つ
  - 段の中の行が無い空白では、隣の段の行や入れ物のグリップを出さない（直上の行の下端のそばだけはその行）
  - 箇条書きの下余白線・実余白は各項目の継続行を含む本文下端（入れ子リストの手前）へ一度だけ出す
  - ポインタが静止したまま Enter・Backspace・貼り付け・入力で本文寸法が変わっても、次の描画で同じ辺へ追従させる
- ⌥⇧↑/↓ はキャレットのあるブロック（グリップで選んでいればその選択）を前後の兄弟と入れ替える。入れ物の端では外へ出る

### Page Breaks And Flow

- 自動改ページ・改段では、本文を実測した行境界で分割し、現在のページ・段の残り高さから流す。「次のページならブロック全体が収まる」だけを理由に丸ごと送らない。枠付き問題も同じ本文フローを使う。手動の改ページ・改段、明示的なまとめ指定、図などの不可分な内容は維持する。部分段組の続きは、その列のまま次ページへ送る
- 改ページ先の本文は、外側の余白だけを元ブロックの計測原点へ合わせ、内部の段落・コード・入れ子枠の組版を保つ。Enterや貼り付けで増えた段落も、元の文書コンテナへまとめて反映する
- 手動改ページより前の行を削除・追加しても、ページ数が変わらない限り、後続ページの本文開始位置は動かさない。文書先頭に本文がなく、空段落だけがある位置では、新たな改ページ・改段を挿入できない。手動改ページ・改段の直後 (空のページ・段) では続けて挿入でき、挿入した数だけ空のページ・段を作る (Word と同じ)。既存の境界の解除は引き続き可能にする
- 文書先頭の本文を削除して空段落だけになった場合は、本文より前に残った手動改ページを同じ編集で解除する。判定は編集面の断片ではなく文書全体で行い、途中の有効な境界は維持する

### Columns

- 部分段組の列は独立して編集する
  - 左列末尾のEnterは左列を伸ばし、右列へ送らない
  - 列境界は段間の全幅で掴める共通ガイドでリサイズする
  - 段組にホバーまたは段組内を編集中は境界を薄く示し、境界に乗るとポインタの高さにつまみを出す
  - ドラッグ中は各列の割合を表示し、均等の近くで吸着する
  - 列は最小幅（段組の10%、元から狭い列はその幅）より狭くせず、さらに寄せると「列を結合」と示して離すと隣へ読み順で結合する
  - クリックだけでは幅を書き換えず、ダブルクリックで隣接2列を均等にし、←/→（Shiftで大きく）でも調整できる
  - 段の空白へブロックを落とすとその段の末尾に入り、段間の行の高さへ落とすとそこに段を足す
  - 枠内外とも複数列を持つ局所段組内には手動改段・改ページを追加しない
- 段間の線は表の罫線と同じ線種・線幅メニューと色パレットで設定する。ページ設定の線は全ページ共通、部分段組の線は枠内外ともブロックごとに適用する。線なし・実線・破線・点線・二重線を選べ、設定画面にプレビューを置く。線は本文の幅・高さや列所属を変えず、編集・Viewer・PDFに同じ設定を描画する。リサイズ用のガイドは編集専用のままにする。
- 部分段組は枠内外とも独立したGrid列で描画し、列幅・段間・境界位置は `features/rendering/core/independent-column-layout.ts`、境界のドラッグは `components/editor/layout-column-resize.ts` を共有する
  - React／Tiptap／静的出力のアダプタで別の列幅計算やCSS multicolによる再配分を行わない
  - Tiptapの `layoutColumn` は列所属を表す編集用の投影で、SigmaDocには保存しない
  - 列所属のない旧box段組だけを互換境界で読み替え、明示された列所属は再配分しない
- 列内の空白をクリックしたときも横位置から列を先に選び、その列内の最寄りの本文へキャレットを置く。低い列の空白を、背の高い隣の列へ渡さない。改段マーカーと幅のドラッグプレビューは編集専用の表示で、本文の高さや保存内容に混ぜない

### Graph Settings

- グラフの詳細設定は右インスペクタへ常設せず、右クリックの「グラフの設定…」か、図形を選んだときのカードの「グラフの設定」から、グラフの横に寄る非モーダルの設定パネル（グリッドの既定幅620px、空き幅に応じて300pxまで縮小）を開く
  - パネルはグラフを覆わない位置（右→左→下の順）に自動配置し、ヘッダーを掴んで移動できる
  - 編集結果をリアルタイムに観察できることが目的なので、backdrop は敷かず、原点指定・塗りつぶし・トリミングを開始してもパネルは閉じない
  - 原点指定と塗りつぶしの実行中は、そのボタンを `aria-pressed` にし、パネル冒頭の `role="status"` 行で次の操作を案内する
  - Esc は、開いているメニューを先に閉じ、次の Esc でパネルを閉じる
- 関数は1枚のカードに、式・種類・線・定義域・ラベルを「ラベル | 操作」の行で常に見せる。関数のカードはパネルの幅いっぱいの1列に並べ、`⋯` には削除だけを置く
- 点と塗りつぶしは、カードのホバー・フォーカスで現れる `⋯` に見た目の操作と削除をまとめる。`⋯` はホバーかクリックでカードの右横にメニューを開き、塗り方は現在値と見本を示すドロップダウンで選ぶ
- 範囲・目盛・軸・軸名は「座標軸と範囲」の節にまとめ、関数のすぐ下に、開いた状態で置く。畳んでいても、範囲の外にあるという警告は見出しの下に出す
- グラフ設定パネル内を操作している間は対象グラフの選択を維持し、本文・空白・別図形へフォーカスまたは選択が移ったらパネルを閉じる
- グラフのダブルクリックは、画像と同じくトリミングを開始する。ただし、下に文章の図形が隠れているときはその文字の編集を優先し、塗りつぶす位置を指定している間は何もしない
- グラフのトリミング、原点指定、塗りつぶしなどの直接操作は右クリックメニューからも開始できるようにする

### 3D Graphs

- 3D教材も2Dグラフと同じ挿入・選択・浮動設定パネルの文法を使う
  - ダブルクリックするとページ上の表示枠そのものがlive viewportになり、設定パネルも開く
  - 立体をクリックすると局所軸と軸間の円弧矢印が出る
  - 円弧ドラッグは回転（Shift中は15度刻み）、軸線のドラッグは平行移動 (どこを掴んでもよい)、正方向の軸端の◆のドラッグはその局所軸だけの拡縮、余白ドラッグは視点、ホイールはcameraの拡大縮小とする
- 3D設定パネルはbackdropを持たず、対象の横へ置き、ドラッグで移動できる。パネル内には別のviewportを置かず、数式・立体・共通部分・表示設定などの編集だけを担う
- 3D教材の表示枠は立体を覗く窓として扱う。枠の縦横比を自由に変えても立体の比率は変形させず、cameraのaspectと表示範囲を追従させる。静止previewも枠いっぱいに切り抜いて表示する
- 3D教材の関数入力は2Dグラフと同じ `MathExpressionInput` とMathLiveを使い、表示用TeXを評価式へ変換してSigmaDocへ保存する
- 立体、共通部分、parameter、数式ラベルは折りたたみセクションで段階的に開示する。切断面の専用UIは置かない。平面との切り口は共通部分のメンバーに平面を混ぜて表す
- 3D教材の数式エラーは入力値を消さず、viewport近くに診断を表示する。重い再計算中も既存の静止previewを保持し、空白へ置き換えない

### Parameters

- 2D・3Dのパラメータ、折りたたみセクション、追加ボタンは共通部品を使う。点・塗りつぶしと3Dの要素は共通のカードのグリッドに並べ、狭いパネルでは1列にする。カードは内容の高さに合わせて配置し、追加ボタンだけで高い空行を作らない
- パラメータの再生値は表示用の状態とし、スライダーと数値表示を同じ値から描く。再生中の毎フレームは保存せず、停止・パネルを閉じるときに最後の値を確定する。2Dの評価用の数値置換は派生投影に限り、SigmaDocの式とパラメータ定義を残す
- 2D・3Dのパラメータ欄に共通の「動画で書き出す」を置き、進捗と保存結果を同じ場所に表示する。「ページ上でも動かす」の指定を優先し、未指定なら範囲のある全パラメータを各自の時計で再生する。動画はSigmaDocからの一時的な投影とし、式や保存値を変更しない。MP4を優先し、対応しない環境ではWebMを使う

### Drawing Tools And Solids

- 点を置いて描く作図ツール（曲線・折れ線・3点円弧）は、置いた点をマーカーで示し、次の操作（点を置く／確定する／1点戻す／取り消す）を画面下部の `role="status"` のピルで常時案内する。折れ線を閉じられる状態では最初の点のマーカーを拡大して当たり判定を可視化する
- 確定後の線の制御点は白丸の頂点ハンドル（位置を動かすもの）で表す。黄◆はパラメータ調整の語彙なので流用しない。セグメント中点の破線ハンドルで点を追加し、頂点の Alt+クリックで削除する。先頭の点は図形の原点なので削除できない
- 立体図形（角錐・角柱・球）は、針金細工として線だけで描く。頂点は線と同じ白丸の頂点ハンドルで、つまんで自由に動かせる（点の追加・削除はしない。頂点の数は立体が決める）。頂点を枠の外へ出したら外接矩形を頂点に合わせて取り直し、回転・反転した図形でも動かしていない頂点が画面上で動かないようにする。見えない辺は既定で破線にする
- 立体の辺は、立体を1つだけ選んでいるときに線を押すと選べる（1回目の押下は図形全体の選択）。ポインタが乗った辺は控えめに、選んだ辺は濃い縁取りで示し、線種と線の太さはその辺だけに効く（直線も曲線も1本ずつ）。上部ツールバーと選択のカードの線種・線幅ボタンは、辺を選んでいる間その辺の値を出す。選択を外す・別の図形を選ぶ・Esc・線以外を押すと辺の選択は外れ、そのときの線種・線の太さの変更は立体の全部の辺に効く。辺の選択は保存しない
- 塗っていない立体は、描かれた線の上だけを掴める（枠の中の空白は本文の空白として扱う）。塗っている立体は塗りの内側も掴める

### Outline

- アウトラインは、メニューやリボンのコマンド・モーダルダイアログにせず、キャンバス左上のレール (`OutlineDock`) から開くカードにする。レールはAIタスクの入口 (`AiTaskDock`) の真下に 8px 空けて左端を揃え、AIタスクの入口が無い構成では一番上から始める。高さを持たない台に載せ、本文を押し下げない
- 畳んでいる間は、項目ごとの短い線を縦に並べたレールだけを出す (幅 36px、線の太さ 2px)。線の長さで段を表す (最上位 20px、以下 15・11・8px)。線は `--text-muted` の薄い色で、問題はさらに薄くする。項目が多いときは1行 8px から 3px まで詰め、それでも収まらない分は切る
- いま読んでいる項目 (本文の表示域の上3割の線より上に頭がある最後の項目) の線を `--primary` で示す。レールが切れるほど長いときは、この線が見える位置へレールの中だけを送る
- レールへのホバー・フォーカスでその場にカードが開き、開いている間レールは消す。ポインタが外へ出る (100ms の猶予。中にフォーカスがある間は閉じない)・フォーカスが外へ出る・Esc・外側のクリック・項目の選択・右上の × で閉じる。背景は暗くせず、開いたまま本文をスクロールできる
- カードは題名・件数・× と、見出し・節・問題の一覧。最も大きい見出しを左端にして1段 14px で字下げし (最大3段)、問題は直前の見出しの一段下に小さく薄く置く。見出し番号を表示する教材では番号を前置する。項目を押すとその位置へ移って選択する。選択中の項目は地色で、いま読んでいる項目は文字色 (`--primary`) で示す。↑↓・Home・End で行を移る
- 見出しも問題も無い教材と、本文を持たないホワイトボードでは入口を出さない。「アウトラインを表示」コマンド (`view.outlineDialog`、既定のキー無し) は同じカードを開き、選択中 (無ければ先頭) の項目へフォーカスを移す。項目が無いときはステータスに理由を出す
- アウトラインを開く入口を、メニューやリボンに重ねて増やさない (同じ一覧を複数の面に持たない)
- 確認は `apps/desktop/tests/electron/outline-dock.spec.ts` を基準にする

### Headers And Footers

- 編集中の帯に「ヘッダー編集中」のような名札や状態表示を重ねない。編集中は帯の枠線と上下のつまみで伝える。
- 帯はダブルクリックで編集に入る。上下のつまみは、触れている間だけ値のピル (「高さ n mm」「上端から n mm」) を出す。高さは 0mm まで下げられ、0mm の帯は線1本で見せる。そのページに出さない帯は、ホバーで破線にし、編集中は中身を薄くする。
- 帯の設定は、帯の右の丸いボタン (帯にカーソルを合わせたときと編集中だけ見える) に集める。押すとカードが開き、ページ番号・総ページ数・「ページ番号 / 総ページ数」・題名を入れる行 (編集中だけ。各行の右に今の値を出す)、表示するページ、そのページだけ内容を変えるスイッチが出る。カードは画面の中に収め、キーボードで開いたらカードの中へフォーカスを移し、Esc でボタンへ戻す。差し込みの書き方 (`{page}`) を覚えなくても入れられるようにする。
- 表示するページは「すべて / 先頭ページのみ / 先頭ページ以外」のまとまりと、そのページだけの例外で決める。ページ設定ダイアログにも同じまとまりを選ぶ項目を置く。まとまりは 2 ページ目以降の既定 (`showOnLaterPages`) で持ち、ページが増えても効く。例外があるときはどのまとまりも選ばず、例外のページを一覧で見せる。どのページにも出さない設定では「どのページにも表示していません」と出す。紙面・プレビュー・PDF・ビューアが同じ判定 (`isRunningRegionShownOnPage`) を使う。
- 「このページだけ内容を変える」は、共通の文字を写してから編集に入り、共通に戻すとそのページ専用の文字を捨てる。変わるのは文字だけで、図形と画像は共通 (カードにそう書く)。ページ専用の文字を持つページは一覧で見せ、「すべて共通に戻す」を出す。
- ページ番号の数え始め (表紙を 0 ページにするなど) はページ設定ダイアログの「ページ番号」に置く。変えるのは `{page}` `{total}` の値だけで、表示するページの指定・ページ専用の中身・ページ移動は組版上のページのままにする。`{total}` は最後のページに出る番号と同じにし、紙面・プレビュー・PDF・ビューアが同じ値 (`getRunningRegionPageNumbers`) を使う。
- 編集面と表示 (印刷・PDF) で見え方を変えない。差し込みの値に編集中だけの色や枠を付けない。
- ヘッダーとフッターの図形は帯の外へはみ出して置ける。Ctrl/Cmd を押しながらドラッグすると範囲で選べる。

### Boxes

- 囲み枠（box）は問題・区切り線・段組・別の枠を含む任意の文書ブロックを包める。内側の3点ボタンは、その枠自身の操作メニューを開く。入れ子の問題も番号・枠・解答欄の予約高・出力対象の設定を保つ
- 囲み枠（box）が祖先にある位置では手動改ページ・外側への改段を追加しない。入れ子の枠・コード・引用・問題内でも同じ規則を適用する。枠内の局所段組にも手動改段を追加しない。操作メニューは枠外と同じ配置・順序を使い、引用内の段組化など実行できない候補は表示しない
- boxのタイトルは本文上でも直接書けるが、確実な入口は ⋯ メニューの「タイトルを編集…」から開く中央ダイアログ (`BoxSettingsDialog`) に置く。タイトルの表示・サブタイトル・スタイル・枠・角・タイトル位置 (「両端」を含む)・色・装飾・パディング・自作の枠をこのダイアログに集約する
- ⋯ はホバーと枠内のフォーカスで出す。同じ操作 (タイトルを編集・boxの設定・コピー・削除) はグリップと右クリックのメニューにも置く
- boxの詳細設定は右インスペクタへ重複して表示しない
- 自作の枠を選んでいるときは、効かない枠・パディングの調整欄を出さず、説明文に置き換える。「自分の枠」の棚は問題の設定と共通にする
- box の設定で決めた見た目は、同じスタイルを次に挿入するときの既定にする

角丸・枠線・背景・タイトル装飾は組み合わせた状態で成立させる。外枠だけに角丸を指定して完了としない。

- タイトル帯、塗り、内側の二重罫、ノート枠も外枠の形に沿わせる。角丸の内側の半径は、枠線の太さや内側への距離を考慮し、四隅に四角い塗り残し・罫線・隙間を作らない
- 箱全体を一律にクリップして、枠にまたがるタイトルや編集用ボタンまで切らない。各装飾の責務に合わせて形を整え、入れ子の箱へ親の装飾や配色を漏らさない
- 切り欠きなど独自の角形状を持つスタイルでは、その形状を保つ。結果に反映されない角丸設定を操作可能なまま表示しない
- 見た目の設定ダイアログには、その箱の実物 (タイトル・サブタイトル・本文・数式) と現在値を反映する即時プレビューを上に留めて置く。紙面と同じ描画・同じ組版幅を使い、スタイル一覧の縮小見本も余白やタイトルを含む全体を表示する
- スタイル一覧は必要時に展開し、普段の調整項目を押し下げすぎない。長いタイトル、大きな余白、狭い画面でもプレビューと操作欄が重なったり欠けたりしないようにする
- 枠の描画を変更したら、全スタイルを実際に描画し、Electronのスクリーンショットを並べて確認する。標準、最小・中間・最大の角丸、太い枠線、色付き背景、タイトル位置を含め、崩れを直してから完了とする
- 空の本文、長いタイトル、入れ子、保存・再読込、印刷表示も確認する。CSSの宣言値やビルド成功だけで、角が正しく描かれたと判断しない

全スタイルの描画・スクリーンショット・保存後の確認は、[Electronのboxデザイン検証](../apps/desktop/tests/electron/box-design.spec.ts)を基準に拡張する。設定のプレビューは `box-settings-preview.spec.ts`、自作の枠は `box-custom-frame.spec.ts` が受け持つ。

### Overlay Coordinates And Editing UI

- 図形の保存位置と画像の移動・リサイズ・トリミングはSigmaDocの座標で扱い、用紙外の座標も編集できる。本文上でのポインター振り分けと印刷の用紙範囲は、それぞれの境界で扱う。
- 表のフローティングツールバーなど編集専用の操作UIは、図形や用紙の子座標面から画面上の独立したポータルへ出す (モーダルの中ではそのモーダルへ出す)。移動範囲を表の幅・高さに制限せず、画面の可視範囲に収める。ズームで操作UI自体を縮小しない。ユーザーが動かすまではスクロール・リサイズに追従し、動かした後は画面上のその位置に留める。
- 本文の右横にコメント欄を描く構成 (Web版・埋め込み) では、欄を用紙端ではなく、overlayのはみ出し量を含む編集範囲の外側へ置き、用紙外の画像や図形を覆わない。デスクトップ版は右上のカードの並び (Comments) に従う。
- 操作UIのドラッグは専用グリップが所有し、図形の移動や本文選択へ伝播させない。編集終了時はポータルと監視処理を破棄する。

## Print And PDF

PDF出力は、アプリUIよりも教材としての読みやすさを優先する。

- 白背景、黒文字を基本にする。ホワイトボードの方眼と点は、用紙にも出す
- 余白、行間、数式サイズを安定させる
- 不要なUI要素は出力しない
- 問題、コメント、解答などの意味単位を崩さない

PDF上の装飾も最小限にし、教材本文、数式、図解が読みやすいことを最優先する。
