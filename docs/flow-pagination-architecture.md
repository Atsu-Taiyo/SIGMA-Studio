# 本文の改ページと編集面

SigmaDoc のブロックはページ境界で分割して保存しない。ページ・段・枠への配置は、その時点の文書と計測から生成する派生情報とする。

## 分割を所有する場所

`features/rendering/core/flow-fragmentation.ts` の `fragmentFlowBlock` が、元ブロックの残量・切断位置・断片番号を管理する。本文ページ、流し込み段組み、独立段組み、problem 内の段組みは、使用可能な領域と次の領域への移動だけを渡す。枠の上下余白や各段の開始位置は容器側の責任とし、内容を切り分けるループを容器ごとに実装しない。

断片は元ブロック内の帯 `sourceOffsetY` と `height`、紙面上の `x / y / width` を持つ。明示改ページは残りが収まる場合も適用する。行計測がある本文は行間で切り、短い末尾という理由だけでページ高を超えて結合しない。用紙より大きい単一行と、分割回数の上限に達した残量は、欠落させず明示的に残す。

## 編集の所有者

続きの `TextFlowEditor` は入力・選択・IME の表示面であり、SigmaDoc を直接更新するコールバックを持たない。`text-flow/fragment-edit-session.ts` が、同じ canvas にある元ブロックの所有者へ変更を渡す。元の編集面が計測用 DOM を同期更新し、その本文・problem・段組みが元から持つ更新コールバックで、新しい兄弟ブロックも含めて保存する。

所有者は固定されたページ番号で探さず、入力時点のブロック ID で解決する。所有者が不在・重複している間は、続きの表示面から文書変更を受け付けない。登録は編集面の寿命に結び付け、異なる canvas で同じ ID が使われても混線させない。履歴と永続化は EditorShell の既存の文書更新経路に集約する。

各表示面には ProseMirror の selection・plugin・composition 状態が残る。これはブラウザの入力機構のための派生状態であり、独立した文書の正本ではない。複数の EditorView に同じ Tiptap Editor の内部状態を無理に共有させない。

## 配置の公開と計測の版

`page-canvas/layout-snapshot.ts` の `PageLayoutSnapshot` が、入力の文書・用紙・ズーム・フォントの版と、本文配置、枠、最初の断片、続きの断片、ページ数、revision を一緒に持つ。React がこの配置を反映した layout effect で、同じ snapshot をキャレットルーターと操作座標の参照先へ公開する。ブロック選択・ドラッグ判定はこの断片矩形でクリップする。未計測・単独利用時の DOM fallback と、ページ割りが測る全文寸法を混同しない。

PDF は引き続き同じ PageCanvas を `PagedRenderSurface` から描き、確定したページ窓を出力する。別の PDF 用分割器は設けない。出力 clone のブロック所有ページも同じ可視矩形から求め、識別 ID の除去によって余白が変わる CSS を使わない。

`text-flow/measurement-revision.ts` は、React が要求した本文の同期キーと、編集 DOM に反映済みの同期キーを別に記録する。一致しない間の計測は採用しない。反映完了イベントで再計測し、「何回か拒否したら古くても採用する」という回数依存の復旧は行わない。入力と同じ大きさのまま行位置が変わる場合もあるため、行矩形キャッシュは編集 transaction の版と DOM の同一性で無効化する。フォント読み込み時は行矩形を破棄する。

## 受入条件

- ページ高・段数・行数を変えても、断片が元の内容を順番に一度ずつ覆う。全再計測と増分計測で結果が一致する。
- 描画された断片とクリック・選択・末尾グリップの対象が一致する。ページ間の空白やクリップされた元表示を選択対象にしない。
- 続きで Enter・文字入力・番号付き項目追加を行っても、兄弟や後続本文を落とさず、保存・再読込後も保持する。
- 手動改ページ、枠付き problem、box の入れ子、数式、長いリスト・引用・コード、ズームをブラウザで検査する。
- 旧本文の計測を採用せず、編集面の入れ替え後に古い登録や DOM のキャッシュを再利用しない。

これらの境界を共通化して再発経路を減らす。ブラウザの行計測や IME に依存する以上、全入力・全字体で不具合がなくなることを保証する設計とは区別する。
