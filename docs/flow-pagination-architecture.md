# 本文の改ページと編集面

SigmaDoc のブロックはページ境界で分割して保存しない。ページ・段・枠への配置は、その時点の文書と計測から生成する派生情報とする。

## 方針: Word と同じ最小送り

自動の改ページは**溢れた行だけ**を次のページ (段組みでは次の段) へ送る。問題・枠付き問題文・全幅エリア・引用・箱・リスト・コードのどれも、収まらないという理由でブロックごとは送らない。容器ごとの特例 (枠付き問題文をまとめて送る、keepWithNext、導入文を次のエリアと離さない、など) は持たない。規則の一覧は `docs/sigma-doc-schema.md` の「自動の改ページ」にある。

## 開ループのパイプライン

```text
本文フロー (DOM: 段幅の自然フロー。配置は兄弟のレイアウトに影響しない相対配置のずらしで与える)
  └─ probeFlow (page-canvas/flow-probe.ts)          自然座標を読む = 表示位置 − 自分が与えた変位
       └─ buildFlowModel (core/pagination)          行モデル: 行・分割できる空白・手動改ページ・独立段組・全幅の区間
            └─ placeFlow (core/pagination)          唯一の配置エンジン。行を領域 (ページ/段) に詰める
                 └─ planFlowRender (core/pagination) 描画の指示: ユニット/ブロックの変位・断片・枠片・改ページ印の位置・ページ数
                      └─ React / ProseMirror の装飾が相対配置のずらし・クリップ・複製で描く
```

**計測はページ割りの答えに依存しない。** 本文は 1 段組でも段組でも「段幅で組んだ 1 本の自然フロー」として DOM に置き、ページ・段への配置はユニット (フロー直下の要素) と編集面の最上位ブロックへの相対配置のずらし (`position: relative` の `top` / `left`) だけで与える。相対配置のずらしは兄弟のレイアウトに影響しないので、配置を変えても自然フローの寸法・折り返し・余白は変わらない (`translate` と違い、ブラウザ自身のキャレット表示・スクロールもずらした位置を正しく扱う)。変位は整数 px にし、1/64px のレイアウト丸めの上でも「表示位置 − 変位 = 自然位置」を厳密に保つ。計測は同じ量を `data-flow-dx` / `data-flow-dy` から読んで差し引く。したがって同じ文書は常に同じ行モデルになり、同じ配置になる。

以前は、隙間 (spacer widget / ユニットの margin) を入れた DOM を読み、適用済みの隙間を推定で引いて自然位置を求めていた。margin の相殺や計測のタイミングで推定がずれると答えが往復し、振動ガードが**誤った配置のまま凍結**した (問題番号が下余白に描かれる、問題文がページ間に描かれる)。この閉ループと振動ガード・凍結・隙間の読み戻しは撤去した。再導入は `page-canvas/architecture.test.ts` が検出する。

段組みのページでは本文を段幅で組み、`.page-flow.page-columns` の右 padding で帯の幅を段幅にする。全幅のエリアはユニット自身が本文幅を持ち、帯から右へはみ出す。段組み専用の絶対配置や余白を削る CSS は無い (1 段組と同じ余白になる)。

## 行モデル (`buildFlowModel`)

- **行**: 縦に重なって描かれるもの (文字の行片・行内数式などの行内原子・空行・問題番号などの付属物) の和集合。重ならない 2 つの行の間でだけ切れる。行内数式は子孫の文字矩形ではなく原子全体の矩形で読む (分数の分子と分母の間で切らない)。空段落・コードの空行は `<br>` の矩形で 1 行になる。
- **見える縁**: 箱 (`.sigma-doc-box-block`)・コード (`pre`)・問題文の枠 (`.with-frame`) の開き側の縁は最初の行の `top` に、閉じ側の縁は最後の行の `fitBottom` に含める。空の箱タイトルは縁の一部、文字のあるタイトルは 1 行。見えない padding / margin は行の間の隙間のまま。
- **空白**: 最小高さ (`areaLayout.*.minHeightMm`) の予約空白と未展開の大量貼り付けは、任意の位置で切れる空白。枠の閉じ側の縁は最後の片と同じ領域に置く (`closingChrome`)。
- **手動改ページ**: 文書の `pagination.break` から作る (紙面の印は PDF 面に描かれないので読まない)。
- **独立段組** (`layoutSection`): 各列が別の流れ (band)。列は均等化しない。後続は最も遅く終わった列の後から始まる。
- **全幅の区間**: 段組みのページで全幅のユニット (`data-flow-span="full"`、`areaLayout.*.columnSpan: "full"` のエリア) が来たら区間を切り替える。

## 配置エンジン (`placeFlow`)

規則は 1 つだけ: 収まる限り今の領域に置き、収まらない行だけを次の領域へ送る。領域の途中では自然配置の間隔を保ち、自動で送った先では段落間の余白を詰める。手動改ページの先では行が持つ `leadingSpace` だけを残す。領域より背の高い 1 行は頭に置いてはみ出させ、後続はその下端より下の領域から始める。段組みの区間の後に全幅の区間が来るときは、最後のページの段組み部分 (行・予約空白・独立段組のどれでも) を左右の段の高さが揃う最小の高さ (0.5px 刻みの二分探索) で詰め直す (最後のページに手動改ページがあるとき、前のページから続く空白・独立段組の途中で始まるときを除く)。ページの途中から始まる段組みの区間は、どの段も最初の行と同じ高さから始める。送る先の領域も途中から始まる (その区間の 2 段目など) ことがあるので、行はページ・段の頭の空の領域に着くまで送り続け、そこにも収まらない行だけを背の高い行として扱う。純関数で決定的。単体テストは `core/pagination/place-flow.test.ts`、乱数の文書 (1 区間 / 段組みと全幅が交互の区間) での不変条件は `place-flow.property.test.ts`。

## 描画 (`planFlowRender` と React)

- ユニット: 相対配置のずらしと `data-flow-dx/dy`。値の無いユニットは前のユニットを継ぐ。
- 最上位ブロック: `ColumnFlowLayoutExtension` の node decoration で、ユニットからの相対のずらし。値の無いブロック (配置前の新しいブロック) は直前のブロックの値を継ぐので、前のページへ戻って見えない。
- ページを跨ぐ最上位ブロック: 正本を最初の帯でクリップし、続きを `EditorBoxBlockFragmentPreview` の複製で描く。帯の端は行と行の間にしか来ない。続きの編集は `text-flow/fragment-edit-session.ts`、キャレットは `text-flow/caret-router.ts` が扱う (下記)。
- 分割された枠付き問題文: 領域ごとの枠片 (`frameFragmentLayouts`)。切れ目の辺は開く。
- 分割されたユニットのサイド注 (括弧) とリサイズつまみ: 自然配置の高さではなく、描いた内容の末尾 (`visualEnds`) まで伸ばす。
- 手動改ページの印: 改ページする前のページの末尾 (直前に置いた行と同じ変位) に描く。
- 変位はレイアウトに影響しないので ResizeObserver は鳴らない。配置が変わったコミットの後に 1 回測り直し、図形のアンカー・キャレット・つまみが使う表示位置を新しい配置に揃える (自然配置は同じなので、配置は同じ答えになる)。

## 編集の所有者

続きの `TextFlowEditor` は入力・選択・IME の表示面であり、SigmaDoc を直接更新するコールバックを持たない。`text-flow/fragment-edit-session.ts` が、同じ canvas にある元ブロックの所有者へ変更を渡す。元の編集面が計測用 DOM を同期更新し、その本文・problem・段組みが元から持つ更新コールバックで、新しい兄弟ブロックも含めて保存する。

所有者は固定されたページ番号で探さず、入力時点のブロック ID で解決する。所有者が不在・重複している間は、続きの表示面から文書変更を受け付けない。

## 配置の公開と計測の版

`page-canvas/layout-snapshot.ts` の `PageLayoutSnapshot` が、入力の文書・用紙・ズーム・フォントの版と、ユニット/ブロックの変位、最初の断片、続きの断片、枠片、ページ数、revision を一緒に持つ。React がこの配置を反映した layout effect で、同じ snapshot をキャレットルーターと操作座標の参照先へ公開する。

`text-flow/measurement-revision.ts` は、React が要求した本文の同期キーと、編集 DOM に反映済みの同期キーを別に記録する。一致しない間の計測は採用しない。行の計測キャッシュ (`flow-probe.ts`) は要素の同一性・編集面の版・寸法で無効化し、フォントの版が変われば捨てる。

PDF は引き続き同じ PageCanvas を `PagedRenderSurface` から描き、確定したページ窓を出力する。別の PDF 用分割器は設けない。

## 受入条件

`tests/e2e/pagination-corpus.spec.ts` が、問題・枠付き問題・最小高さ・引用 (空行入り)・箱・入れ子の箱・リスト・コード・手動改ページ・全幅・部分段組を、1 段組と段組、複数の用紙の高さで組み合わせた教材について、実描画 (`tests/e2e/pagination-audit.ts`) から次を検査する。

1. ページ (段) の本文領域の下端をまたぐ行が無い。行が途中で切れていない。
2. 次の領域の先頭の行は、前の領域の残りに入らない (自然配置での送り量で判定。手動改ページの直後と、閉じ側の縁を伴う行は除く)。領域は (ページ, 区間, 段) で数え、全幅の区間の直前で左右を揃えたページの段から段への送りは除く。
3. すべての行がちょうど 1 回表示される。
4. 読む順: 全幅の行と同じページの行は、文書順で前なら上、後なら下にある。区間の中では (ページ, 段, 縦位置) の順が文書順と一致する。全幅かどうかは実装の印ではなく、ユニットの見た目の幅で判定する。
