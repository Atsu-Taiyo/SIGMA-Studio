# 普段の執筆から書き方を学ぶ

同じワークスペースで最近編集した個人教材の文章そのものから、語尾・文体・教材の書き方手順・TeX数式の書き方を読み取り、次のAI提案に使います。AI案への手直しは補助の手がかりです。自動で行うのは項目の追加だけで、書き換えと削除は本人が確認してから反映します。スキルの作成や評価の操作は要りません。モデルを再学習する機能ではありません。

## 何から学ぶか

手がかりは3種類あり、上から順に主です。

1. **本人が書いた文章**。同じワークスペースの個人教材のうち、更新が新しい10件を読みます（既定値）。1件あたり2万字、1回の見直しで合計10万字までです。本文、問題の導入文・問題文・コメント・解答、見出し、リスト、囲み内の文章が対象で、図形やコメントスレッドは読みません。
2. **採用したAI案への手直し**。AI案を採用（確定）したあとで本人が直した差分です。採用前に直す場合と同じく、採用後に直すことも多いので、こちらを最も強い手直しとして扱います。
3. **自分の文章への手直し**。AIが関わっていない段落を直した差分です。

AIが書いたまま手が入っていない部分は、本人の書き方として数えません。採用を保存するときに、AIが書き込んだブロックごとに内容のハッシュを記録しておき、見直しのときにその内容のままのブロックを読み飛ばします。少し直しただけのAI文も文章全体は数えず、直した差分だけを手直しとして使います。ほとんど書き直した場合（文字の重なりが半分未満）は本人の文章として数えます。

### 採用したAI案のその後

AIが書き込んだブロックは、その後の扱いを記録します。

| 結果 | 判定 |
|---|---|
| そのまま（kept） | 採用後の編集・保存を経ても内容が変わっていない |
| 手直し（edited） | 本人が内容を変えた。変更前後を手直しの実例にする |
| 取り消し（reverted） | 採用前の内容に戻した、またはAIが足したブロックを消した。書き方の実例にはしない |
| 却下（rejected） | 提案を採用しなかった。理由は推測しない |

採用そのものは書き方の根拠にしません。却下と取り消しは件数だけを記録し、見直しを早めるきっかけにします。「そのまま」が続いている間は、学んだ項目を古い扱いにしません。

## 何を読み取るか

読み取り方は2つあります。

### 端末の中での集計

項目は決まった観点だけで、文面は固定の定型文から作ります。教材の文章や数式がメモに写ることはありません。

- 語尾・文体: 解説の常体／丁寧体、設問の結び（〜を求めよ／〜しなさい／〜してください）、結論のつなぎ語（よって・したがって・ゆえに・以上より）、句読点の組み合わせ（、。／，．など）
- 教材の書き方手順: 小問番号の形（(1)・（1）・①・[1]）、問題に解答欄を書くか、コメント欄に補足を添えるか
- 数式と数学の記法（下の表）。手直しからは、これに加えてインライン／ディスプレイ、伸縮括弧、空き、揃え環境、数式に続く句読点も読みます

| 観点 | 読み分けるもの |
|---|---|
| 分数 | `\frac`／`\dfrac`／`\tfrac`（文中の数式だけ） |
| 乗算記号 | `\cdot`／`\times` |
| ベクトル・太字 | `\vec`／`\overrightarrow`／`\vv`／太字（`\mathbf`・`\bm`） |
| 不等号 | `\leqq`／`\leq`／`\leqslant` |
| 積分の d | `d`／`\mathrm{d}`、`dx` の前に空きを入れるか |
| 導関数 | `\frac{dy}{dx}`／`\frac{d}{dx}` を前に置く形／`y'`・`f'(x)` |
| 組合せ | `{}_n\mathrm{C}_r`／`{}_nC_r`／`\binom{n}{r}` |
| 式番号 | `\tag`／式の右の丸数字／式の右の括弧つき数字 |
| 長い等式の置き場所 | ディスプレイ数式／文中 |
| 文中の和・積分・極限 | `\displaystyle`・`\limits` を付けるか |
| 括弧 | `\left…\right`／`\bigl` などで大きさを指定／そのままの括弧（分数などを囲むとき） |
| 集合 | 条件の区切り（`\mid`／縦線／コロン）、数の集合（`\mathbb`／太字） |
| 区間 | `[a, b]` の括弧／`]a, b[` の向き（`\in` の後ろだけを読む） |
| ∴・∵ | 式の中で `\therefore`・`\because` を使うか |
| 単位 | 直立体（`\mathrm`）／`\text`／通常の文字 |
| 角度の度 | `^\circ`／`°` |
| よく使うコマンド | 省略の点（`\cdots`／`\ldots`／`\dots`）、矢印（`\to`／`\rightarrow`）、ならば、同値、近似（`\fallingdotseq`／`\approx`／`\simeq`）、上線（`\overline`／`\bar`） |

  1つの数式が2つの書き方を混ぜているときは、どちらの票にも数えません。「コマンドを付けない」こと自体は項目にしません（付けない数式は割合を下げる票としてだけ数えます）。導関数・組合せ・式番号・区間・集合の区切りのように式の形が変わるものは、手直しの差分からは読まず、本人が書いた数式からだけ読みます。

根拠の基準は次のとおりです。

- 文章から: 同じ書き方が独立した3ブロック以上にあり、その観点で書き方が分かるブロックの7割以上を占めること。一度だけの書き方は項目にしません。
- 手直しから: 異なる教材・ブロックの2箇所以上で、同じ向きの変更が繰り返されること。値や数学的内容が変わった数式（値の訂正、通常微分から偏微分など）は根拠にしません。採用後の手直しは、向きが割れたときに2倍に数えます。
- 両方があって食い違うときは、手直しを優先します。
- 「解答欄を書かない」のような否定形の項目は作りません。

### 使っているAIによる要約

決まった観点では拾えない書き方（説明の順序、補足の入れ方など）は、本人がすでに使っているAI（ChatGPT・Claude・Antigravity のうち、最後にAIへ依頼したときのもの）に要約させます。新しい送信先は増やしません。設定の「AIで書き方を要約する」でオフにでき、オフのときは端末の中の集計だけで学びます。

- 送るのは、本人が書いた文章の抜粋（1ブロック300字まで、合計6,000字まで）、自分の文章への手直しの例（最大6件）、いまのメモの項目、本人が退けた項目です。AIが書いたままの文章、採用したAI案への手直し（中身の大半がAIの文のため）、共有教材、ほかのワークスペースの教材、根拠の教材がすべて共有・移動・削除された項目、指示の書き換えを狙った文に見える抜粋は送りません。
- 呼び出しはツールなしの一回きりで、保存やAIへの依頼を待たせません。まだ一度もAIへ依頼していない場合、本人の文章が400字に満たない場合は呼びません。
- 同じ文章を二度は送りません。自動の見直しでは、ワークスペースごとに6時間に1回までです（「今すぐ見直す」はこの間隔を待ちません）。
- 返ってきた内容はデータとして扱います。1回に最大3項目、1項目は60字以内の1文です。この文は本人が読む前にメモに入り、あとのAI依頼にも渡るので、書き方以外の内容は入口で落とします（直さずに捨てます）。採らないのは次の文です: 指示の書き換えを狙った文、ファイル・コマンド・認証情報・返答の扱いに触れる文、AIやメモの読み手に呼びかける文（「あなた」「AI」「システム」など）、ほかの項目の扱いを決める文（「無視」「優先」「以後」など）、何をするか・してよいかを述べる文（「安全」「禁止」「架空」「必ず」など）、2文以上の文、書き方を表す語（書く・述べる・結ぶ・表記・語尾・数式 など）を含まない文、パスや記号（`/` `~` `$` など）を含む文、日本語のメモに対する英語の文、教材の文章を14字以上そのまま含む文。全角の英字などは半角に直してから調べ、「」などで引用した言い回しは例として除いたうえで、残りの文が書き方について述べているかを見ます。この検査は語の並びによる判定で、意味までは読めません。書き方の体裁をとった不適切な文をすべて落とせるわけではないので、下の表示・記録・取り消しと、AI依頼側の「learned は言い回し・体裁・表記にだけ適用する」という指示を併せて守りにしています。AI要約の項目は、確認待ちを含めて合計10件までです。
- 検査を通った項目は、承認を待たずにメモへ追加します（オーナーの判断）。その代わりに次を守ります。
  - 設定画面に「AIが追加した項目」として、追加日と「AIが追加」の印を付けて並べます。項目ごとの「削除」で、その項目だけを消せます（項目のIDで消すので、同じ文面の自分の行は残ります。メモの行を消すのと同じ扱いで、追加し直しません）。
  - 追加は台帳に `add-summary` として、追加した文とともに記録します。「1つ前に戻す」で取り消せます。取り消した文は「退けた項目」に入り、AIが同じ文を挙げても追加しません（やり直すと解除されます）。
  - AIへ渡すたびに、同じ検査をもう一度通します。検査を通らなくなった文や、キーと文面が合わない文は、通常のAI依頼にも次のAI要約にも渡さず、設定画面の「渡していない行」の件数に数えます。
  - 保存は、台帳、`memory.json`、`learned.md` の順に書きます。途中で止まっても、AIが追加した文が「本人が書いた行」として取り込まれることはありません（置き換え前のメモのハッシュを `learned.pending` に置き、次の読み込みで中断を見分けます）。
  - メモが上限に達しているときは追加せず、「確認待ち」にします。
- AI要約がほかにできるのは、以前自分が挙げた項目がいまも確認できるという印だけです。項目の書き換え・削除はできません。
- 本人が消した・見送った要約の項目は、言い換えも含めて挙げないようAIに伝え、同じ文は二度と追加しません。
- 失敗や読めない返事は `ledger.log` に記録するだけで、端末の中の集計の結果はそのまま残ります。

## いつ見直すか

見直しは、保存やAIへの依頼とは別に、裏で動きます。保存処理は見直しを待たず、AIへの依頼の中で学習作業をさせることもありません。

きっかけは次のいずれかです。編集が15秒止まってから始めます。

- 採用後の手直しが2件たまった
- 却下・取り消しが2件たまった
- 保存が5回たまった
- 変更があり、前回の見直しから30分以上たっている（初回を含む）

設定画面の「今すぐ見直す」でも実行できます。見直しが失敗しても、保存とAIへの依頼には影響しません。失敗は `data/logs/ledger.log` に記録します。

## メモがどう育つか

学んだ内容は、ワークスペースごとの「学んだ書き方」に1項目1文で持ちます。同じ事実を全体のメモとワークスペースのメモの両方には書きません。

自動の見直しができるのは追加までです。逆の根拠がどれだけ強くても、既存の項目の書き換えと削除は自動では行いません。

| 変更 | 扱い |
|---|---|
| 端末の中の集計による新しい項目の追加、根拠の件数・確認日時の更新 | 自動で行う |
| AI要約が挙げた項目の追加 | 検査を通ったものを自動で追加し、「AIが追加」と表示する。台帳に記録し、取り消し・削除ができる |
| 既存の項目と食い違う根拠が増えた | 追記せず、書き換えを「確認待ち」にする。本人が反映または見送りを選ぶ |
| 確認できないまま45日たった、または根拠の教材がなくなった | 削除を「確認待ち」にする。本人が反映するまで項目は残り、AIにも渡し続ける |
| メモが上限（3,000字）に達した | 追加を「確認待ち」にする。古い項目を黙って捨てない |

確認待ちの変更は、提案時点の文面と今の文面が同じ場合だけ反映できます。画面に出ていた提案が裏の見直しで別の内容に差し替わった場合、前の提案の「反映する」は効きません（提案ごとに別のIDを持ちます）。見送った変更は、同じ内容では再び提案しません。削除の提案は、同じ書き方がまた確認できれば取り下げます。

例外は1つだけです。根拠の教材がすべて共有・移動・削除された項目は、削除の確認を待たずにAIへ渡すのをやめます（メモには残ります）。共有教材から学んだ内容を使わないという既存の約束を優先するためです。

### 本人が編集した項目

「学んだ書き方」は設定画面でも、表示されているパスのファイルでも編集できます。

- 書き換えた行・足した行は本人の項目になり、自動では更新しません。
- 消した項目は、リセットするまで学び直しません。確認待ちの削除を反映した項目も同じです。
- 編集は項目ごとに扱います。1行直しても、ほかの項目の自動更新は続きます。

### 変更の記録と取り消し

項目の追加・確認待ち・反映・見送り・本人の編集は、誰が何をどう変えたかを `ledger.jsonl` に追記します（変更前後のメモのハッシュ付き、最大400行）。「1つ前に戻す」で直前の変更を取り消せます。もう一度押すと取り消しをやり直します。戻せるのは直近5回分です。

## AIに渡す内容

依頼を始めた時点のメモを固定して渡します。依頼の途中でメモは変わりません。

- 全体・ワークスペースの手動メモ（各2,200字まで）
- 学んだ書き方の項目。根拠の教材がすべて共有・移動・削除された項目は渡しません
- 手直しの実例を最大6件（合計7,000字まで）。採用後の手直し、対象の教材、新しい順に選びます。同じワークスペースのものだけです
- 本人が手編集した教材のタイトル・fileId・blockId を最大8件。本文は渡しません

優先順位は、今回の依頼と明示指示、手動メモ、学んだ書き方の順です。

AIへ渡す前に、手動メモ・学んだ書き方・実例を検査します。指示の書き換えを狙った文、認証情報を求める文、不可視文字を含む行や実例は渡しません。ファイルは書き換えず、渡さなかった行数を設定画面に表示します。

## 設定と保存先

AI設定の「全体」「ワークスペース」にそれぞれ「書き方の学習」があります。

- 全体: 学習のオン／オフ、AIで書き方を要約するかどうか、全体の手動メモ、すべてのリセット
- ワークスペース: 学習のオン／オフ、AIで書き方を要約するかどうか、手動メモ、学んだ書き方（編集・今すぐ見直す・1つ前に戻す）、確認待ちの変更、AIが追加した項目（「AIが追加」の印と削除）、項目ごとの根拠、採用したAI案のその後の件数

オフにすると、その範囲の収集・見直し・AIでの利用がすべて止まります。オフの間の編集を、あとからさかのぼって取り込むことはありません。リセットは、その範囲の実例・学んだ書き方・AI案のその後の件数・変更の記録を消します。手動メモと教材本体は残します。

オフの間とリセットの後も残すものが1つあります。「どのブロックをAIが書いたか、その後に手が入ったか」の印（内容のハッシュと状態だけで、本文は持ちません）です。これを消すと、学習を再開したときにAIの文章を本人の文章として数え、AI要約にも送ってしまうためです。この印は件数には数えません。

保存先はElectronのユーザーデータ内です（開発時は既定で `tmp/desktop-dev-profile`）。

```text
data/ai-authoring-style/
  examples.json        # 手直しの実例（最大160件・2MB）
  outcomes.json        # AIが書いたブロックのハッシュとその後、却下の件数（本文は持たない。最大3,000ブロック）
  user.md              # 全体の手動メモ
  settings.json        # 全体のオン／オフ、AI要約のオン／オフ
  provider.json        # 最後に使ったAI（要約の依頼先）
  workspaces/<workspaceIdのSHA256>/
    workspace.md       # ワークスペースの手動メモ
    learned.md         # 学んだ書き方（人が読む・編集する形）
    memory.json        # 項目・根拠・確認待ち・取り消し用の控え
    ledger.jsonl       # 変更の記録
    settings.json
```

ファイルは一時ファイルから置き換えて保存します。更新は専用のOSファイルロックで直列化します。教材の読み取りはロックの外で行い、反映の直前に、オン／オフと教材の所属を確かめ直します。

## アカウントでの同期

設定の「アカウントで同期する（Pro）」は Pro プラン（試用中を含む）の機能です。既定はオンで、Pro のアカウントでサインインしていれば、下の内容をアカウントに保存し、同じアカウントのほかの端末と合わせます。オフにするか、Pro でないあいだは、何も送らず、サーバーにも問い合わせません。この端末での学習は、プランに関係なくそのまま動きます。

何を同期するかは、置き場所で決まります。

| 対象 | 同期 |
|---|---|
| 自分用のメモ（`user.md`）、全体の学習／AI要約のオン・オフ、最後に使ったAIの名前 | アカウント単位で同期 |
| 共有ワークスペースの書き方（学んだ項目・`workspace.md`・そのワークスペースのオン・オフ・台帳） | 共有ワークスペースごとに同期。サーバーがそのワークスペースに付けている ID で結びます（名前は使いません） |
| 共有していないワークスペースの書き方 | 同期しません。この端末だけに保存します |
| アプリの設定のうち、表示言語・ショートカット・カスタムコマンド・AIのWeb検索のオン・オフ | アカウント単位で同期 |
| エージェント用の指示・スキル | 同期しません |

- Pro かどうかは、共有の人数上限やプランの画面と同じ判定（サーバーが返すプラン）で決めます。サーバー側でも、Pro でないアカウントの読み書きは断ります。Pro でなくなったあとも、「サーバーのデータを削除」は使えます。
- 学習は今のところ、共有教材を読みません（「読むもの」を参照）。そのため共有ワークスペースで実際に同期されるのは、手で書いたメモとオン・オフが中心です。
- アプリの設定で送らないもの: AIのコマンドの場所（パス）、読み込んだフォントと本文の既定フォント（ファイルが端末にあるため）、新しい教材が引き継ぐ用紙設定（画像を含むことがあるため）、検証済みのAI案を自動で反映する設定（端末ごとに本人が決めるため）、サインインの情報。ブラウザ側に保存している細かな表示の好み（AIのモデル選択、リボンの形など）も、今は送りません。
- アプリの設定は項目ごとに合わせます。ショートカットとカスタムコマンドは1件ずつ比べるので、2台で別々の割り当てを変えても両方残ります。初めて合わせるときに食い違う項目は、アカウント側を採ります。ただしAIのWeb検索は、どちらかがオフならオフにします。別の端末の変更が入ると、開いている画面の言語とショートカットもその場で切り替わります。

- 保存先は共有サーバーです。読めるのは本人だけで、共有相手にも見せません。
- 送るのは、項目（文面・種類・根拠の件数・日付）、消した項目の印、見送った変更の印、退けたAIの文、手動メモ（全体・ワークスペース）、学習とAI要約のオン／オフ、最後に使ったAIの名前、台帳の直近200行です。
- 送らないのは、共有していないワークスペースの内容、教材の本文、手直しの実例（`examples.json`）、AIが書いたブロックの記録（`outcomes.json`）、教材の ID、ワークスペースの名前、確認待ちの変更、「1つ前に戻す」の履歴、エージェント用の指示です。
- 端末のファイルが正です。同期は、前回合わせた内容・手元・サーバーの3つを比べて合わせます。
  - 項目: 片方だけが変えたものを採ります。消したことは必ず勝ち、別の端末が学び直すこともありません。
  - 手動メモ: 行ごとに合わせます。どちらかが足した行は残ります。
  - オン／オフ: オフにしたことは全部の端末に届きます。オンにしたことはアカウントに記録するだけで、ほかの端末は本人がその端末でオンにするまでオフのままです（同期が学習やAI要約を勝手にオンにすることはありません）。初めて合わせるときは、アカウント側がオフならこの端末もオフにします。
  - リセット: リセットしたほうが勝ち、古い端末の内容では生き返りません。受け取った端末は、その端末で集めた実例も捨てます。
  - 初めて合わせるとき（同期をオンにした直後、「このアカウントと同期し直す」の直後）は、リセットの回数を比べず、両方の項目を残します。同期をオンにしたあと、まだ一度も合わせないうちにリセットした場合は、リセットを優先します。
  - 合わせた結果がメモの3,000字、項目400件、消した項目の印100件、全体256KBのどれかを超えるときは、その回は何も変えずに止め、設定画面に知らせます。台帳だけは、古い行から落として収めます。
- 別の端末から来た自動の項目は、文面を信用せず、種類と値から作り直します。作れないもの、検査を通らないものは使いません（新しい版のアプリが書いた項目は、サーバーには残します）。
- 別の端末から来た手書きの行は、1行・500字以内で、指示文の検査を通ったものだけを取り込みます。手動メモと合わせて、AIへ渡す直前の検査（2行にまたがる指示文、全角で書いた指示文も見ます）を毎回通します。
- 別の端末で学んだ項目は、この端末に根拠の教材が無くてもAIに渡します。どこかの端末に根拠があるあいだは「根拠が無くなった」とは扱いません。45日確認が無ければ、削除を確認待ちに出します。
- 同期で入った変更は、台帳に `sync-add`・`sync-update`・`sync-remove` として残ります。「1つ前に戻す」は手元の操作だけを戻し、別の端末の変更は残します。この3種類の行はその端末にだけ残し、アカウントには送りません。
- オフラインやサーバーの不調では、手元だけで今までどおり動き、次の機会（手元の変更の5秒後、起動時、15分ごと、設定画面を開いたとき、「今すぐ同期」）にやり直します。
- サインアウトしても手元の内容は消えません。別のアカウントでサインインしたときは自動では混ぜず、「このアカウントと同期し直す」を押したときだけ合わせます。通信は、用意したときのアカウントでサインインしているあいだだけ行い、途中でアカウントが替わる・同期をオフにする・サーバーのデータを削除する、のどれかが起きたら、その回の同期はそこで止めます。
- 「サーバーのデータを削除」で、アカウントに保存した内容（書き方とアプリの設定）を消して同期をオフにします。手元の内容は残ります。ほかの端末は、次に同期しようとしたときに削除に気づいて、同期をオフにします（データを送り直しません）。
- 同期の状態は `data/ai-authoring-style/sync.json` に持ちます（端末の乱数 ID、アカウント ID のハッシュ、前回合わせた内容）。

## プライバシーと制約

- 集計は端末の中で行います。外部へ出るのは、本人が行う通常のAI依頼に添える上記の内容と、AI要約のために送る抜粋だけです。どちらも送り先は本人が使っているAIで、新しい送信先はありません。AI要約をオフにすれば、見直しのために外部のAIを呼ぶことはありません。
- Pro のアカウントでサインインしていて「アカウントで同期する（Pro）」がオン（既定）のとき、自分用のメモ、共有ワークスペースの書き方、一部のアプリ設定を共有サーバーに保存します（上の「アカウントでの同期」）。共有していないワークスペースで学んだ内容と教材の本文は送りません。
- AI要約の項目は、AIが書いた文です。定型文ではないので、本人の文章の言い回しが短く入る可能性があります（14字以上の引用は採りません）。
- 共有教材、共有の同期で入った変更、バックアップの復元、時刻だけの変更、失敗した保存、オフの間の編集は対象外です。教材を共有・移動・削除すると、その教材の実例とAI案の記録を次の読み取りで消します。
- この機能を入れる前に採用したAI案は区別できません。その文章は本人の文章として数えます。AI案の記録は3,000ブロックまでです。超えた分は古いものから消えますが、印を失った教材は、それ以降は本人の文章として読みません（AIの文章を本人のものとして数えないためです）。
- 語尾の読み取りは日本語の教材を前提にしています。英語だけの教材からは、TeXと構成の項目だけを読み取ります。
- 却下の理由、図形、コメントスレッドからは学びません。
- 以前の方式で作った自動要約は引き継ぎません。本人が手で直していた場合だけ、その行を本人の項目として残します。
