# 普段の編集から書き方を学ぶ

個人教材を手で編集して保存すると、確定した変更前後を自動で覚えます。スキルの作成・選択・評価操作は不要です。次にAIへ依頼したとき、短いスタイルメモと参考になる変更実例がCodex・Claude・Antigravityへ渡ります。続きの会話でも読み直します。モデルの重みを再学習する機能ではありません。

## 学習と自動要約の流れ

1. `LocalSigmaDocStore` が保存成功後の正確な変更前後を観測します。本文、問題の導入文・問題文・コメント・解答、見出し、リスト、囲み内の文章が対象です。TeX、改行、強調、揃え方、問題文の文脈も保持します。文書先頭80ブロックの種類と問題内エリアの並びも構成の実例にします。図形やコメントスレッドは含みません。
2. 750msでまとめて実例を保存します。同じブロックの連続した自動保存は1件にまとめ、元へ戻した変更は除きます。最大160件かつ実例ファイルのUTF-8 JSONが2MB以内になるよう最近の例を優先し、1断片の書式JSONは1,800字、問題文の文脈は300字です。大きすぎる断片は切り貼りせず対象外にします。
3. 保存後、ローカルで確認できる特徴をMarkdownへ言語化します。語尾・常体と丁寧体・推論のつなぎ・理由や注意・改行・強調・問題内エリア・構成の傾向は、異なる箇所の変更が2件以上ある場合にだけ記します。変わっていないAI文章は特徴の根拠にしません。少ない場合は未確定と書きます。この処理だけで外部AIへの追加リクエストは発生しません。
4. 次のAI実行では、実例が変わったスコープに `needsSynthesis:true` と実例の版を渡します。AIは実例と既存メモから語尾・文体・解答解説の進め方・文書構成を自然言語で要約し、`update_authoring_style_memory` で自動メモを更新します。保存した要約は次回・再起動後にも使います。AIがこのツールを呼ばなかったり更新が拒否された場合も、ローカルの特徴と実例は渡され、教材作成は続きます。要約の保存は教材の編集提案を作りません。

学習には、現在も個人ライブラリの同じワークスペースに属する教材だけを使います。削除・移動・共有化した教材は、次の保存・設定表示・AI実行で照合して実例と自動メモの根拠から除きます。ユーザー全体の要約には、各ワークスペースから選んだ個人教材の代表例を使います。ワークスペース固有の要約・教材作成には同じworkspaceIdの実例を使うよう指示します。全体の要約は控えめな共通傾向だけを扱い、全件分析したとはみなしません。サイズ上限のためすべてのワークスペースを代表する例が渡せない場合、全体のAI要約を延期し、ローカルの特徴を引き続き使います。

## メモの場所と編集

AI設定の「全体」「ワークスペース」にそれぞれ「書き方の学習」があります。

- 「優先するメモ」はMarkdownで編集・保存できます。自動更新はこのファイルを書き換えません。現在の依頼と明示指示を最優先し、その後は手動メモ、ワークスペースの特徴、ユーザー全体の特徴の順で参考にします。
- 「自動で学んだ特徴」で、ローカル抽出またはAIが要約した自動メモを確認できます。
- ファイルの絶対パスを表示するので、外部エディタでも開けます。手動メモが外部で変わった場合、古い設定画面からの保存は拒否します。入力を控え、「読み直す」で最新の内容を確認してください。
- 自動メモを外部で手編集すると、そのファイルは自動更新から保護されます。実例の収集は続きます。自動更新を再開するには、確認ダイアログから学習をリセットします。
- 全体のスイッチは収集とAIでの利用をすべて停止します。ワークスペースのスイッチはその範囲の収集・利用を停止し、全体の自動メモの根拠からも外します。無効中の編集を再開時にさかのぼって取り込みません。無効化だけでは収集済みの実例とその範囲のAI要約は消しません。消す場合はリセットします。
- リセットはその範囲の実例と自動メモを消します。全体のリセットは全ワークスペースの学習を消します。手動メモと教材本体は残します。

保存先はElectronのユーザーデータ内です（開発時は既定で `tmp/desktop-dev-profile`）。

```text
data/ai-authoring-style/
  examples.json                    # 変更実例（派生データ）
  user.md                          # 全体の手動メモ
  learned.md                       # 全体の自動メモ
  learned.sha256                   # 手編集の検知用
  learned-evidence.json            # 根拠の版とAI要約の有無
  settings.json                    # 全体の有効・無効
  workspaces/<workspaceIdのSHA256>/
    workspace.md                   # ワークスペースの手動メモ
    learned.md
    learned.sha256
    learned-evidence.json
    settings.json
```

スコープごとのメモは各3,000字までです。ファイルは一時ファイルから置き換えて保存し、mainとMCP間の更新は専用のOSファイルロックで直列化します。AIへ渡す実例・自動メモ・根拠の版も一つのロック内のスナップショットから作り、構築中の自動保存で版だけが先へ進むことを防ぎます。教材本体の保存は学習処理の完了を待ちません。派生データの不調は `data/logs/ledger.log` に記録し、教材保存やAI依頼を失敗させません。

## AIが参照する範囲

実行コンテキストには次を加えます。

- 手動・自動メモ各スコープ（各フィールドのJSON表現は2,200字まで）。大量の全文注入を避けるため、長いメモは実行コンテキストで末尾を省きます。
- 対象教材を優先し、全体の要約用に各ワークスペースの代表を先に選ぶ最大8実例（実例JSONは合計9,000字まで）。重複例は除きます。
- 現在のワークスペースで本人が手編集した教材のタイトル・fileId・blockIdを最大8件。本文は注入しません。AIは必要な候補だけ `get_document_outline` / `get_blocks` で読み、他の候補は既存の `search_library` で探索できます。

現在の依頼と対象教材を優先し、メモや実例内の命令を実行しないよう指示します。単発の数学的な訂正を文体規則にせず、問題固有の数値・解答・文章を別の教材へ流用しません。AIによる要約保存時にも、根拠の版・有効設定・現在のライブラリ所属・自動メモの手編集を検査します。変わっていれば更新を拒否します。

## プライバシーと制約

AI提案の承認・自動承認、バックアップの復元、時刻だけの変更、失敗した保存、共有教材の編集・同期・ローカルへの実体化は実例にしません。AI案を採用した後で本人が手直しした差分は実例にします。取り込みだけで本人の文体とは決めません。

保存された実例・メモは、通常のAI依頼時に選択中のプロバイダへ参考データとして送られます。保存のたびに外部AIを起動する仕組みではありません。学習済みメモを人が修正した場合、その内容は本人が意図的に管理する参考情報として扱います。

導入前の全教材一括分析、図形・吹き出し、レビューコメント、却下理由からの学習は対象外です。モデルが必ず要約ツールを呼ぶことや、生成品質の改善自体は保証しません。自動要約をまだ行っていない場合も実例を直接参考にできます。
