# 普段の執筆から書き方を学ぶ

同じワークスペースで最近編集した個人教材の文章そのものから、語尾・文体・教材の書き方手順・TeX数式の書き方を読み取り、次のAI提案に使います。教材の構成（問題の置き方、枠囲み、見出し、コメント、余白、ブロックの並び）も同じように読み取ります。AI案への手直しは補助の手がかりです。検査を通った項目の追加・書き換え・削除は自動で反映し、台帳に記録します（元に戻せます）。本人が書いた項目と手動メモは、自動では変えません。スキルの作成や評価の操作は要りません。モデルを再学習する機能ではありません。

## 何から学ぶか

手がかりは3種類あり、上から順に主です。

1. **本人が書いた文章**。同じワークスペースの個人教材のうち、更新が新しい10件を読みます（既定値）。共有ワークスペースでは、メンバー全員の教材が対象です（「共有ワークスペースの書き方」）。1件あたり2万字、1回の見直しで合計10万字までです。本文、問題の導入文・問題文・コメント・解答、見出し、リスト、囲み内の文章が対象で、図形やコメントスレッドは読みません。
2. **採用したAI案への手直し**。AI案を採用（確定）したあとで本人が直した差分です。採用前に直す場合と同じく、採用後に直すことも多いので、こちらを最も強い手直しとして扱います。
3. **自分の文章への手直し**。AIが関わっていない段落を直した差分です。

AIが書いたまま手が入っていない部分は、本人の書き方として数えません。採用を保存するときに、AIが書き込んだブロックごとに内容のハッシュを記録しておき、見直しのときにその内容のままのブロックを読み飛ばします。少し直しただけのAI文も文章全体は数えず、直した差分だけを手直しとして使います。ほとんど書き直した場合（文字の重なりが半分未満）は本人の文章として数えます。

### 採用したAI案のその後

AIが書き込んだブロックは、その後の扱いを記録します。

| 結果 | 判定 |
|---|---|
| そのまま（kept） | 採用後の編集・保存を経ても内容が変わっていない |
| 手直し（edited） | 本人が内容を変えた。変更前後を手直しの実例にする |
| 取り消し（reverted） | 採用前の内容に戻した、またはAIが足したブロックを消した。書き方の実例にはしない |
| 却下（rejected） | 提案を採用しなかった。理由は推測しない |

採用そのものは書き方の根拠にしません。却下と取り消しは件数だけを記録し、見直しを早めるきっかけにします。「そのまま」が続いている間は、学んだ項目を古い扱いにしません。

## 何を読み取るか

読み取り方は2つあります。

### 端末の中での集計

項目は決まった観点だけで、文面は固定の定型文から作ります。教材の文章や数式がメモに写ることはありません。

- 語尾・文体: 解説の常体／丁寧体、設問の結び（〜を求めよ／〜しなさい／〜してください）、結論のつなぎ語（よって・したがって・ゆえに・以上より）、句読点の組み合わせ（、。／，．など）
- 教材の書き方手順: 小問番号の形（(1)・（1）・①・[1]）、問題に解答欄を書くか、コメント欄に補足を添えるか
- 数式と数学の記法（下の表）。手直しからは、これに加えてインライン／ディスプレイ、伸縮括弧、空き、揃え環境、数式に続く句読点も読みます

| 観点 | 読み分けるもの |
|---|---|
| 分数 | `\frac`／`\dfrac`／`\tfrac`（文中の数式だけ） |
| 乗算記号 | `\cdot`／`\times` |
| ベクトル・太字 | `\vec`／`\overrightarrow`／`\vv`／太字（`\mathbf`・`\bm`） |
| 不等号 | `\leqq`／`\leq`／`\leqslant` |
| 積分の d | `d`／`\mathrm{d}`、`dx` の前に空きを入れるか |
| 導関数 | `\frac{dy}{dx}`／`\frac{d}{dx}` を前に置く形／`y'`・`f'(x)` |
| 組合せ | `{}_n\mathrm{C}_r`／`{}_nC_r`／`\binom{n}{r}` |
| 式番号 | `\tag`／式の右の丸数字／式の右の括弧つき数字 |
| 長い等式の置き場所 | ディスプレイ数式／文中 |
| 文中の和・積分・極限 | `\displaystyle`・`\limits` を付けるか |
| 括弧 | `\left…\right`／`\bigl` などで大きさを指定／そのままの括弧（分数などを囲むとき） |
| 集合 | 条件の区切り（`\mid`／縦線／コロン）、数の集合（`\mathbb`／太字） |
| 区間 | `[a, b]` の括弧／`]a, b[` の向き（`\in` の後ろだけを読む） |
| ∴・∵ | 式の中で `\therefore`・`\because` を使うか |
| 単位 | 直立体（`\mathrm`）／`\text`／通常の文字 |
| 角度の度 | `^\circ`／`°` |
| よく使うコマンド | 省略の点（`\cdots`／`\ldots`／`\dots`）、矢印（`\to`／`\rightarrow`）、ならば、同値、近似（`\fallingdotseq`／`\approx`／`\simeq`）、上線（`\overline`／`\bar`） |

  1つの数式が2つの書き方を混ぜているときは、どちらの票にも数えません。「コマンドを付けない」こと自体は項目にしません（付けない数式は割合を下げる票としてだけ数えます）。導関数・組合せ・式番号・区間・集合の区切りのように式の形が変わるものは、手直しの差分からは読まず、本人が書いた数式からだけ読みます。

根拠の基準は次のとおりです。

- 文章から: 同じ書き方が独立した3ブロック以上にあり、その観点で書き方が分かるブロックの7割以上を占めること。一度だけの書き方は項目にしません。
- 手直しから: 異なる教材・ブロックの2箇所以上で、同じ向きの変更が繰り返されること。値や数学的内容が変わった数式（値の訂正、通常微分から偏微分など）は根拠にしません。採用後の手直しは、向きが割れたときに2倍に数えます。
- 両方があって食い違うときは、手直しを優先します。
- 「解答欄を書かない」のような、何もしないだけの項目は作りません（例外は「問題にコメントは付けない」で、付けるかどうかが構成の好みだからです）。ただし「書かない」が多数になったときは、反対のことを言っている既存の項目を外します。

### 構成・レイアウト

文章の書き方と同じ集計で、教材の組み立て方も読み取ります。読むのはブロックの種類と設定だけで、値はすべて決まった一覧の中から選びます。項目は「学んだ書き方」の「構成・レイアウト」の節に入ります。

| 観点 | 数える単位 | 項目の例 |
|---|---|---|
| 問題の番号 | 問題 | 自動の番号を付けない／全角数字で付ける |
| 問題の書き出しのラベル | 問題 | 「問1」「第1問」「【1】」「例題」などの形で書き始める |
| 問題の枠 | 問題 | 問題を枠で囲む（枠の種類つき） |
| 導入文の行 | 問題 | 導入文を書く／導入文の行は使わない |
| コメントの有無と位置 | 問題 | コメント欄に添える／問題の直後・直前に枠囲みで置く／付けない |
| 解答を書き込む余白 | 問題 | 欄の高さを取る／問題の下に余白を空ける |
| 小問の並べ方 | 問題 | 番号付きリスト（(1)・(a) など）で並べる／段落の先頭に番号を書く |
| 枠囲みの種類 | 枠囲み | よく使う種類、タイトルを付けるかどうか、サブタイトル |
| 何を囲むか | 枠囲み | 定義／定理・公式／ポイント・注意／例／まとめ／解答・解説／例題・練習問題を、どの種類の枠で囲むか（タイトルの語から判定） |
| 見出しの書き方 | 見出し | 「第1章」「1.」「1.1」「§1」【 】、先頭の記号、中央揃え・右揃え |
| 見出しの階層、タイトルとサブタイトル | 教材 | 見出しを何段階まで使うか、先頭にタイトルを置くか、直後にサブタイトルを付けるか |
| ページ | 教材 | 段組の数、用紙のサイズと向き |
| ブロックの並び | 教材 | 「見出し → 枠囲み → 問題」のような並び。同じ並びの繰り返しは「〔本文 → 問題〕の繰り返し」と書く |

- 基準は文章と同じです。問題・枠囲み・見出しの観点は3つ以上のブロックで7割以上、教材の単位の観点は3件以上の教材で7割以上そろったときだけ項目にします。
- AIが作ってだれも手を入れていないブロックは数えません（そのブロックの中に本人が書いた文章が1つも無いとき）。教材の単位の観点は、本人が書いたブロックがAIのままのブロック以上あるときだけ数えます（長すぎて文章を読まないブロックや、1回に読む量を超えた先のブロックも、この数には入れます）。
- 既定のまま（枠なし、1段、A4縦、番号は半角数字 など）は項目にしません。
- 問題の中（導入文・問題文・コメント・解答）に置いた枠囲みと見出しも、同じ観点で数えます。
- 教材の文字はメモに入りません。見出しや枠のタイトルは、決まった形（「第1章」で始まる、「公式」を含む など）に当てはまるかどうかだけを見ます。
- 手直しの差分からは構成を読みません（文章だけです）。
- AI要約がオンのときは、教材ごとのブロックの種類の並び（例: `heading1 / box(theorembox,theorem) / problem[prompt,solution] x3`。本文は含みません。1件300字まで）も送り、構成についての項目を挙げてもらいます。

### 使っているAIによる要約

決まった観点では拾えない書き方（説明の順序、補足の入れ方など）は、本人がすでに使っているAI（ChatGPT・Claude・Antigravity のうち、最後にAIへ依頼したときのもの）に要約させます。新しい送信先は増やしません。設定の「AIで書き方を要約する」でオフにでき、オフのときは端末の中の集計だけで学びます。

- 送るのは、本人が書いた文章の抜粋（1ブロック300字まで、合計6,000字まで）、自分の文章への手直しの例（最大6件）、いまのメモの項目、本人が退けた項目です。AIが書いたままの文章、採用したAI案への手直し（中身の大半がAIの文のため）、共有していないワークスペースの中で個別に共有した教材、ほかのワークスペースの教材、根拠の教材がすべて共有・移動・削除された項目、指示の書き換えを狙った文に見える抜粋は送りません。
- 呼び出しはツールなしの一回きりで、保存やAIへの依頼を待たせません。まだ一度もAIへ依頼していない場合、本人の文章が400字に満たない場合は呼びません。
- 同じ文章を二度は送りません。自動の見直しでは、ワークスペースごとに6時間に1回までです（「今すぐ見直す」はこの間隔を待ちません）。
- 返ってきた内容はデータとして扱います。1回に最大3項目、1項目は60字以内の1文です。この文は本人が読む前にメモに入り、あとのAI依頼にも渡るので、書き方以外の内容は入口で落とします（直さずに捨てます）。採らないのは次の文です: 指示の書き換えを狙った文、ファイル・コマンド・認証情報・返答の扱いに触れる文、AIやメモの読み手に呼びかける文（「あなた」「AI」「システム」など）、ほかの項目の扱いを決める文（「無視」「優先」「以後」など）、何をするか・してよいかを述べる文（「安全」「禁止」「架空」「必ず」など）、2文以上の文、書き方を表す語（書く・述べる・結ぶ・表記・語尾・数式 など）を含まない文、パスや記号（`/` `~` `$` など）を含む文、日本語のメモに対する英語の文、教材の文章を14字以上そのまま含む文。全角の英字などは半角に直してから調べ、「」などで引用した言い回しは例として除いたうえで、残りの文が書き方について述べているかを見ます。この検査は語の並びによる判定で、意味までは読めません。書き方の体裁をとった不適切な文をすべて落とせるわけではないので、下の表示・記録・取り消しと、AI依頼側の「learned は言い回し・体裁・表記にだけ適用する」という指示を併せて守りにしています。AI要約の項目は、確認待ちを含めて合計10件までです。
- 検査を通った項目は、承認を待たずにメモへ追加します（オーナーの判断）。その代わりに次を守ります。
  - 設定画面に「AIが追加した項目」として、追加日と「AIが追加」の印を付けて並べます。項目ごとの「削除」で、その項目だけを消せます（項目のIDで消すので、同じ文面の自分の行は残ります。メモの行を消すのと同じ扱いで、追加し直しません）。
  - 追加は台帳に `add-summary` として、追加した文とともに記録します。「1つ前に戻す」で取り消せます。取り消した文は「退けた項目」に入り、AIが同じ文を挙げても追加しません（やり直すと解除されます）。
  - AIへ渡すたびに、同じ検査をもう一度通します。検査を通らなくなった文や、キーと文面が合わない文は、通常のAI依頼にも次のAI要約にも渡さず、設定画面の「渡していない行」の件数に数えます。
  - 保存は、台帳、`memory.json`、`learned.md` の順に書きます。途中で止まっても、AIが追加した文が「本人が書いた行」として取り込まれることはありません（置き換え前のメモのハッシュを `learned.pending` に置き、次の読み込みで中断を見分けます）。
  - メモが上限に達しているときは追加せず、「確認待ち」にします。
- AI要約がほかにできるのは、以前自分が挙げた項目がいまも確認できるという印だけです。項目の言い直し・取り下げはできません。
  - 45日確認されていない自分の項目は、AIにもう一度聞いて確認されなかったときに外します（聞いていないあいだは外しません。集計では AI の文を確認できないためです）。台帳に `auto-remove` として残り、「自動で反映した変更」から元に戻せます。「書き換え・削除も自動で反映する」がオフのときは、削除を確認待ちに出します。
  - 読めなかった教材があった回などの「全部は読めなかった回」と、AIの返事を待つあいだに教材が保存し直された回は、確認されなくても外しません（共有教材は一覧の日時が本文の編集で動かないので、返事を反映する前に読み直して、聞いたときの内容と同じかを確かめます）。その回の問い合わせは「済み」と記録せず、全部読めるようになったら同じ内容でもう一度聞きます。
  - 返事が決めた形（`add` と `confirm` の配列を持つJSON。追加は節と文の組、番号は挙げた候補のどれかを指す整数）でないときは、読めない返事として捨てます。「確認されなかった」とは数えません。節の名前が決めたもの以外の追加が混じっているときは、その追加だけを捨て、その返事では「確認されなかった」とも数えません。
- 本人が消した・見送った要約の項目は、言い換えも含めて挙げないようAIに伝え、同じ文は二度と追加しません。
- 失敗や読めない返事は `ledger.log` に記録するだけで、端末の中の集計の結果はそのまま残ります。

## いつ見直すか

見直しは、保存やAIへの依頼とは別に、裏で動きます。保存処理は見直しを待たず、AIへの依頼の中で学習作業をさせることもありません。

きっかけは次のいずれかです。編集が15秒止まってから始めます。

- 採用後の手直しが2件たまった
- 却下・取り消しが2件たまった
- 保存が5回たまった
- 変更があり、前回の見直しから30分以上たっている（初回を含む）

設定画面の「今すぐ見直す」でも実行できます。見直しが失敗しても、保存とAIへの依頼には影響しません。失敗は `data/logs/ledger.log` に記録します。

## メモがどう育つか

学んだ内容は、ワークスペースごとの「学んだ書き方」に1項目1文で持ちます。同じ事実を全体のメモとワークスペースのメモの両方には書きません。

自動の見直しは、検査を通った追加・書き換え・削除を、確認なしで反映します。対象は自動の項目だけです。本人が書いた項目、手動メモ（`workspace.md`・`user.md`）は、自動では書き換えも削除もしません。

| 変更 | 扱い |
|---|---|
| 端末の中の集計による新しい項目の追加、根拠の件数・確認日時の更新 | 自動で行う |
| AI要約が挙げた項目の追加 | 検査を通ったものを自動で追加し、「AIが追加」と表示する |
| 既存の項目と食い違う根拠が増えた（基準は追加と同じ） | 追記せず、その項目を書き換える |
| 既存の項目と反対に「何もしない」が多数になった | その項目を外す |
| 確認できないまま45日たった、または根拠の教材がなくなった | その項目を外す。消した扱いにはしないので、同じ書き方がまた確認できれば学び直す |
| メモが上限（4,000字）に達した | 追加・書き換えを「確認待ち」にする。古い項目を黙って捨てない |

- 書き換えと削除は台帳に `auto-rewrite`・`auto-remove` として、理由（食い違い・確認できない）と変更前後の文とともに残します。
- 設定画面の「自動で反映した変更」に直近20件を並べ、1件ずつ「元に戻す」で前の内容に戻せます。戻した変更は、同じ内容ではもう自動で行いません。本人が断った値（追加を取り消した・見送った値、書き換えを戻したときの戻す前の値）は、追加としても書き換えとしても、別の端末からの同期でも、その項目には入れません（この記録は400件まで持ちます。足すのは本人の操作だけです）。その項目を本人があとから手で消したときと、ワークスペースの書き方がリセットされたあとは、一覧から外れ、戻せません。「1つ前に戻す」でも取り消せ、その場合も同じ変更は繰り返しません（取り消しをやり直すと解除されます）。
- 読めなかった教材があった回、読んでいる間に保存し直された教材があった回、共有ワークスペースで共有教材の一覧が分からなかった回（サインアウト中・読み込み中・オフライン・取得の失敗。見直しの途中で読めるようになった場合も含む）は、書き換えと削除を反映せず「確認待ち」にします（見えていない根拠で変えないためです）。一覧が分からなかった回は、「根拠の教材がなくなった」とも扱いません。共有だったかどうかは端末に覚えておくので（同期で内容を受け取っただけのワークスペースも含む）、再起動してサインアウトのまま見直しても同じです。共有していないワークスペースは、サインインしていなくてもふだんどおり反映します。
- 「書き換え・削除も自動で反映する」をオフにすると、書き換えと削除は「確認待ち」に並び、本人が反映または見送りを選びます（追加はオフでも自動です）。既定はオンです。スイッチは全体とワークスペースにあり、どちらかがオフならオフです。この設定は端末に保存し、同期しません。

確認待ちの変更は、提案時点の文面と今の文面が同じ場合だけ反映できます。画面に出ていた提案が裏の見直しで別の内容に差し替わった場合、前の提案の「反映する」は効きません（提案ごとに別のIDを持ちます）。見送った変更は、同じ内容では再び提案しません。削除の提案は、同じ書き方がまた確認できれば取り下げます。スイッチをオンに戻すと、確認待ちだった書き換えと削除は次の見直しで反映されます。

根拠の教材がすべて共有・移動・削除された項目は、見直しを待たずにAIへ渡すのをやめます。個別に共有した教材から学んだ内容を使わないという既存の約束を優先するためです（共有ワークスペースの教材は根拠として数えます）。

### 本人が編集した項目

「学んだ書き方」は設定画面でも、表示されているパスのファイルでも編集できます。

- 書き換えた行・足した行は本人の項目になり、自動では更新しません。
- 消した項目は、リセットするまで学び直しません。確認待ちの削除を反映した項目も同じです。
- 編集は項目ごとに扱います。1行直しても、ほかの項目の自動更新は続きます。

### 変更の記録と取り消し

項目の追加・自動の書き換えと削除・確認待ち・反映・見送り・元に戻す操作・本人の編集は、誰が何をどう変えたかを `ledger.jsonl` に追記します（変更前後のメモのハッシュ付き、最大400行）。「1つ前に戻す」で直前の変更を取り消せます。もう一度押すと取り消しをやり直します。戻せるのは直近5回分です。

## AIに渡す内容

依頼を始めた時点のメモを固定して渡します。依頼の途中でメモは変わりません。

- 全体・ワークスペースの手動メモ（各2,200字まで）
- 学んだ書き方の項目（全文。上限は4,000字。手動メモとは別の資料として渡すので、メモが長くても末尾が切れません。TeXのコマンドや改行で符号化後に長くなっても切りません。制御文字は空白として渡し、検査も空白に読み替えた形で行います）。根拠の教材がすべて共有・移動・削除された項目は渡しません。以前は渡す分を2,200字で切っていて、上限近くまで育ったメモは末尾の節が渡っていませんでした。いまは全文を渡します
- 手直しの実例を最大6件（合計7,000字まで）。採用後の手直し、対象の教材、新しい順に選びます。同じワークスペースのものだけです
- 本人が手編集した教材のタイトル・fileId・blockId を最大8件。本文は渡しません

優先順位は、今回の依頼と明示指示、手動メモ、学んだ書き方の順です。

「構成・レイアウト」の項目は、AIが教材やブロック（問題・枠囲み・見出しなど）を新しく作るときに合わせるよう伝えます。既にある教材の構成を、依頼なしに組み替えることはさせません。

学んだ書き方の上限を3,000字から4,000字にしたのは、構成・レイアウトの節が増えたためです（最大で20項目ほど、1項目25〜45字）。上限に達すると追加が「確認待ち」になり、自動で入らなくなるので、節が1つ増えた分の余地を足しました。手動メモの上限（3,000字）は変えていません。

AIへ渡す前に、手動メモ・学んだ書き方・実例を検査します。指示の書き換えを狙った文、認証情報を求める文、不可視文字を含む行や実例は渡しません。ファイルは書き換えず、渡さなかった行数を設定画面に表示します。

## 設定と保存先

AI設定の「全体」「ワークスペース」にそれぞれ「書き方の学習」があります。

- 全体: 学習のオン／オフ、AIで書き方を要約するかどうか、書き換え・削除も自動で反映するかどうか、全体の手動メモ、すべてのリセット
- ワークスペース: 学習のオン／オフ、AIで書き方を要約するかどうか、書き換え・削除も自動で反映するかどうか、手動メモ、学んだ書き方（編集・今すぐ見直す・1つ前に戻す）、自動で反映した変更（元に戻す）、確認待ちの変更、AIが追加した項目（「AIが追加」の印と削除）、項目ごとの根拠、採用したAI案のその後の件数

オフにすると、その範囲の収集・見直し・AIでの利用がすべて止まります。オフの間の編集を、あとからさかのぼって取り込むことはありません。リセットは、その範囲の実例・学んだ書き方・AI案のその後の件数・変更の記録を消します。手動メモと教材本体は残します。

オフの間とリセットの後も残すものが1つあります。「どのブロックをAIが書いたか、その後に手が入ったか」の印（内容のハッシュと状態だけで、本文は持ちません）です。これを消すと、学習を再開したときにAIの文章を本人の文章として数え、AI要約にも送ってしまうためです。この印は件数には数えません。

保存先はElectronのユーザーデータ内です（開発時は既定で `tmp/desktop-dev-profile`）。

```text
data/ai-authoring-style/
  examples.json        # 手直しの実例（最大160件・2MB）
  outcomes.json        # AIが書いたブロックのハッシュとその後、却下の件数（本文は持たない。最大3,000ブロック）
  user.md              # 全体の手動メモ
  settings.json        # 全体のオン／オフ、AI要約のオン／オフ
  provider.json        # 最後に使ったAI（要約の依頼先）
  workspaces/<workspaceIdのSHA256>/
    workspace.md       # ワークスペースの手動メモ
    learned.md         # 学んだ書き方（人が読む・編集する形）
    memory.json        # 項目・根拠・確認待ち・取り消し用の控え
    ledger.jsonl       # 変更の記録
    settings.json
```

ファイルは一時ファイルから置き換えて保存します。更新は専用のOSファイルロックで直列化します。教材の読み取りはロックの外で行い、反映の直前に、オン／オフと教材の所属を確かめ直します。

## アカウントでの同期

設定の「アカウントで同期する（Pro）」は Pro プラン（試用中を含む）の機能です。既定はオンで、Pro のアカウントでサインインしていれば、下の内容をアカウントに保存し、同じアカウントのほかの端末と合わせます。オフにするか、Pro でないあいだは、何も送らず、サーバーにも問い合わせません。この端末での学習は、プランに関係なくそのまま動きます。

何を同期するかは、置き場所で決まります。

| 対象 | 同期 |
|---|---|
| 自分用のメモ（`user.md`）、全体の学習／AI要約のオン・オフ、最後に使ったAIの名前 | アカウント単位で同期 |
| 共有ワークスペースの書き方（学んだ項目・`workspace.md`・そのワークスペースのオン・オフ・台帳） | ワークスペースに1つだけ保存し、そのワークスペースのメンバー全員で合わせます。サーバーがそのワークスペースに付けている ID で結びます（名前は使いません） |
| 共有していないワークスペースの書き方 | 同期しません。この端末だけに保存します |
| アプリの設定のうち、表示言語・ショートカット・カスタムコマンド・AIのWeb検索のオン・オフ | アカウント単位で同期 |
| エージェント用の指示・スキル | 同期しません |

- Pro かどうかは、共有の人数上限やプランの画面と同じ判定（サーバーが返すプラン）で決めます。サーバー側でも、Pro でないアカウントの読み書きは断ります。Pro でなくなったあとも、「サーバーのデータを削除」は使えます。
- アプリの設定で送らないもの: AIのコマンドの場所（パス）、読み込んだフォントと本文の既定フォント（ファイルが端末にあるため）、新しい教材が引き継ぐ用紙設定（画像を含むことがあるため）、検証済みのAI案を自動で反映する設定（端末ごとに本人が決めるため）、サインインの情報。ブラウザ側に保存している細かな表示の好み（AIのモデル選択、リボンの形など）も、今は送りません。
- アプリの設定は項目ごとに合わせます。ショートカットとカスタムコマンドは1件ずつ比べるので、2台で別々の割り当てを変えても両方残ります。初めて合わせるときに食い違う項目は、アカウント側を採ります。ただしAIのWeb検索は、どちらかがオフならオフにします。別の端末の変更が入ると、開いている画面の言語とショートカットもその場で切り替わります。

- 保存先は共有サーバーです。自分用のメモとアプリの設定は本人の置き場にあり、読めるのは本人だけで、共有相手にも見せません。
- 共有ワークスペースの書き方は、本人のものではなくワークスペースのものです（下の「共有ワークスペースの書き方」）。
- 送るのは、項目（文面・種類・根拠の件数・日付）、消した項目の印、見送った変更の印、退けたAIの文、手動メモ（全体・ワークスペース）、学習とAI要約のオン／オフ、最後に使ったAIの名前、台帳の直近200行です。
- 送らないのは、共有していないワークスペースの内容、教材の本文、手直しの実例（`examples.json`）、AIが書いたブロックの記録（`outcomes.json`）、教材の ID、ワークスペースの名前、確認待ちの変更、「1つ前に戻す」の履歴、エージェント用の指示です。
- 端末のファイルが正です。同期は、前回合わせた内容・手元・サーバーの3つを比べて合わせます。
  - 項目: 片方だけが変えたものを採ります。消したことは必ず勝ち、別の端末が学び直すこともありません。
  - 手動メモ: 行ごとに合わせます。どちらかが足した行は残ります。
  - オン／オフ: オフにしたことは全部の端末に届きます。オンにしたことはアカウントに記録するだけで、ほかの端末は本人がその端末でオンにするまでオフのままです（同期が学習やAI要約を勝手にオンにすることはありません）。初めて合わせるときは、アカウント側がオフならこの端末もオフにします。
  - リセット: リセットしたほうが勝ち、古い端末の内容では生き返りません。受け取った端末は、その端末で集めた実例も捨てます。
  - 初めて合わせるとき（同期をオンにした直後、「このアカウントと同期し直す」の直後）は、リセットの回数を比べず、両方の項目を残します。ワークスペースの内容を一度も受け取っていない端末でのリセットは、その端末の中身を消すだけで、メンバーが共有している内容は消しません。一度受け取ったあとのリセットは、ワークスペースの書き方のリセットで、オーナーと管理者だけができます。
  - 合わせた結果が学んだ書き方の4,000字、手動メモの3,000字、項目400件、消した項目の印100件、全体256KBのどれかを超えるときは、その回は何も変えずに止め、設定画面に知らせます。台帳だけは、古い行から落として収めます。
- 別の端末から来た自動の項目は、文面を信用せず、種類と値から作り直します。作れないもの、検査を通らないものは使いません（新しい版のアプリが書いた項目は、サーバーには残します）。
- 別の端末から来た手書きの行は、1行・500字以内で、指示文の検査を通ったものだけを取り込みます。手動メモと合わせて、AIへ渡す直前の検査（2行にまたがる指示文、全角で書いた指示文も見ます）を毎回通します。
- ある端末の見直しが「確認できない」として外した項目でも、別の端末の見直しがそのあと確認していれば残します（外した端末にも戻ります）。本人が消した項目と、追加を取り消した・見送った項目は、消えたままです（初めて合わせるときも、片方が持っていれば戻る、ということはありません）。AI要約が挙げた項目も同じです。「元に戻す」で戻した変更は、別の端末の見直しが同じ変更をしていても、戻したほうが勝ちます。
- 別の端末で学んだ項目は、この端末に根拠の教材が無くてもAIに渡します。どこかの端末に根拠があるあいだは「根拠が無くなった」とは扱いません。45日確認が無ければ外します（自動の反映がオフなら、削除を確認待ちに出します）。
- 同期で入った変更は、台帳に `sync-add`・`sync-update`・`sync-remove` として残ります。「1つ前に戻す」は手元の操作だけを戻し、別の端末の変更は残します。この3種類の行はその端末にだけ残し、アカウントには送りません。
- オフラインやサーバーの不調では、手元だけで今までどおり動き、次の機会（手元の変更の5秒後、起動時、15分ごと、設定画面を開いたとき、「今すぐ同期」）にやり直します。
- サインアウトしても手元の内容は消えません。別のアカウントでサインインしたときは自動では混ぜず、「このアカウントと同期し直す」を押したときだけ合わせます。通信は、用意したときのアカウントでサインインしているあいだだけ行い、途中でアカウントが替わる・同期をオフにする・サーバーのデータを削除する、のどれかが起きたら、その回の同期はそこで止めます。
- 「サーバーのデータを削除」で、アカウントに保存した内容（自分用のメモ・設定とアプリの設定）を消して同期をオフにします。共有ワークスペースの書き方はメンバー全員のものなので、ここでは消えません。手元の内容は残ります。ほかの端末は、次に同期しようとしたときに削除に気づいて、同期をオフにします（データを送り直しません）。
- 同期の状態は `data/ai-authoring-style/sync.json` に持ちます（端末の乱数 ID、アカウント ID のハッシュ、前回合わせた内容）。

## 共有ワークスペースの書き方

共有ワークスペース（ワークスペースごと共有したもの）の書き方は、メンバー全員で1つです。学んだ項目・`workspace.md`・そのワークスペースのオン／オフ・台帳がこれに当たります。自分用のメモ（`user.md`）とアプリの設定は、これまでどおり本人だけのものです。

### 学び方

- そのワークスペースの教材の全体から学びます。自分が書いた分だけでなく、ほかのメンバーが書いた教材も読みます。読むだけで、教材は変えません。
- 1回の見直しで読むのは、ほかのワークスペースと同じく、最近更新された10件・合計10万字までです。
- 決まりは個人のワークスペースと同じです。3ブロック以上・70%以上そろった書き方だけを項目にし（構成・レイアウトも同じ）、検査を通った追加・書き換え・削除を自動で反映して、変更は台帳に残します。メンバーの端末が自動で書き換えた項目は、内容が変わった別の項目として、ほかのメンバーではまた承認待ちになります。「元に戻す」は、その変更をした端末でだけできます。
- 共有教材の保存はこの端末を通らないので、保存の回数では見直しを始めません。代わりに、ワークスペースの教材の一覧（どの教材が、いつ更新されたか）が前回の見直しから変わっていて、前回から30分以上たっていれば、そのワークスペースでAIに依頼したとき、または設定画面でそのワークスペースを開いたときに見直します。教材の中身だけが書き換わった場合は一覧に表れないので、一覧が同じでも前回から6時間たてば見直します。読めなかった教材があった回は「見た」と記録せず、30分後にやり直します。「今すぐ見直す」はいつでも使えます。
- AI要約がオンなら、見直しのときに共有教材の抜粋（ほかのメンバーが書いた分も含む）を、本人が最後に使ったAIへ送ります。オフなら送りません。スイッチは全体とワークスペースの2つで、どちらかがオフなら送りません。
- 共有教材では、どの文をAIが書いたかをこの端末で追えません（採用の記録は個人の教材だけにあります）。AIが書いて誰も直していない文も、教材の文として数えます。手直しの実例も共有教材からは集めません。
- 共有していないワークスペースの中で、教材やフォルダだけを共有したものは、これまでどおり読みません。

### 同期

- 保存先は、本人の置き場ではなくワークスペースの置き場です。メンバーかどうかはサーバーが確かめ、メンバーでない人には読ませも書かせもしません。
- 読むのも書くのも、その本人が Pro（試用中を含む）であることが要ります。ほかのメンバーが Pro でも代わりにはなりません。Pro でないメンバーは、この端末の中だけで学びます。
- 書けるのは、教材を編集できるメンバー（オーナー・管理者・編集者）です。閲覧のみのメンバーは、ほかのメンバーの内容を受け取りますが、自分の端末での変更（メモ、項目の追加・削除、オン／オフ）はほかのメンバーには届きません。画面にその旨を出します。
- 全員分のリセットと、学習・AI要約を全員分オン／オフにすることは、オーナーと管理者だけができます（下の「オーナー・管理者だけができること」）。
- 複数のメンバーが同時に学んだり書いたりしても、1つに合わさります。書き込みは「読んだ版のまま変わっていなければ」という条件つきで、先を越されたら読み直して合わせ直します。同じ書き方は同じ項目として数えるので、2人が同時に学んでも項目は重複しません。
- 合わせ方は端末どうしと同じです（上の「アカウントでの同期」）。メンバーの1人が消した項目はほかのメンバーの端末でも消え、学び直しません。
- ほかのメンバーが書いた項目とメモは、本人が承認するまで本人のAIに渡しません（下の「ほかのメンバーが書いたものの承認」）。別の端末から来たものと同じ検査（1行・500字以内、指示文の検査、AIへ渡す直前の検査）は、承認したあとも毎回通します。
- 送るのは学習の結果だけです。教材の本文、手直しの実例、教材の ID は送りません。台帳には項目の文面が入るので、メンバーが書いた行はほかのメンバーの台帳にも出ます。
- メンバーから外れると、そのワークスペースについては何も読まず、何も送りません（ほかの同期は続きます）。この端末に受け取ってあった内容は残ります。
- 「サーバーのデータを削除」は本人の置き場だけを消します。ワークスペースの書き方は、ワークスペースを削除するか共有を止めたときに、サーバーが消します。Pro をやめても、サーバーの内容は残ります。

### オーナー・管理者だけができること

全員に効く操作は、オーナーと管理者だけができます。編集者は書き方の中身（項目・メモ）を編集できますが、次の2つはできません。

| 操作 | オーナー・管理者 | 編集者・閲覧のみ |
|---|---|---|
| 学んだ書き方のリセット | 全員の学んだ項目を消します | できません（ボタンを押せません）。「すべてリセット」も、そのワークスペースは飛ばします |
| 学習／AI要約のオン・オフ | 全員分を切り替えます。オフは全員に届き、オンは各自が自分の端末で入れ直します | この端末だけオフにできます（送りません）。全体がオフのものは、オンにできません |

- サーバーも同じことを確かめます。オーナー・管理者以外が、リセットの回数や全体のオン／オフを変えた内容を書こうとすると断ります（`ADMIN_REQUIRED`）。アプリを書き換えても通りません。
- まだ誰も保存していないワークスペースに編集者が最初に書くときは、リセット0回・どちらもオンの状態でしか書けません。
- ワークスペースの内容を一度も受け取っていない端末（同期をオフにしていた、Pro でなかった）では、書き方はその端末だけのものなので、リセットもオン／オフも本人ができます。受け取ったあとは上の表のとおりです。
- 役割が変わったことを端末がまだ知らない場合は、サーバーが断った時点でその回の書き込みをやめ、サーバーの内容を正とします。その端末で行ったリセットは無かったことにし、役割が分かった時点でメンバーの内容を受け取り直します（「全部消した」として送ることはありません）。

### ほかのメンバーが書いたものの承認

ほかのメンバーが書いた項目とメモの行は、本人が承認したものだけを本人のAIに渡します。画面と `learned.md`・`workspace.md` には全部出ますが、承認前のものはAIへの依頼にも、AI要約に添える「いまある項目」にも入れません。

| 何が | だれのものとして扱うか | 承認 |
|---|---|---|
| 自分がこの端末で書いた項目・メモの行、この端末の見直しが追加した項目 | 自分 | 不要 |
| 自分の別の端末で書いた・学んだ・承認したもの | 自分（アカウントで判定） | 不要 |
| ほかのメンバーの端末が自動で学んだ項目（集計による定型文） | ほかのメンバー | 要る。ただし、この端末の見直しが同じ項目を教材から自分で見つけたら不要 |
| ほかのメンバーの端末でAI要約が追加した項目 | ほかのメンバー | 要る |
| ほかのメンバーが手で書いた項目・メモの行 | ほかのメンバー | 要る |
| ほかのメンバーが退けたAIの文（「もう提案しない」印） | ほかのメンバー | 承認の対象にせず、自分のAIには渡さない |

- 設定画面のワークスペースのページに「ほかのメンバーが書いた項目（承認待ち）」を出します。1件ずつ「承認する」「使わない」を選べ、「すべて承認する」もあります。「使わない」にしたものは一覧から外して畳んだ欄に移し、あとから承認できます。
- 承認も「使わない」も本人だけに効きます。項目そのものは消えず、ほかのメンバーには何も変わりません（全員から消したいときは、項目やメモの行を消します）。
- 承認は項目の内容（自動の項目は種類と値、手書きの行は文面）に付きます。だれかが文面を変えると別の項目になり、変えた人のものとして、ほかのメンバーではまた承認待ちになります。ほかのメンバーの行を自分で書き換えたら、自分の行です。
- だれが認めたかは、ワークスペースの内容に「アカウントごとの、認めた項目の印の一覧」（`vouchers`）として持ちます。印は内容のハッシュの先頭20桁で、文面は含みません。自分の別の端末は、自分の一覧にある項目を承認なしで使います。
- サーバーは、ほかの人の一覧に印を足す書き込みを断ります（`VOUCHER_MISMATCH`）。足せるのは本人の一覧だけなので、ほかのメンバーが「あなたが認めた」ことにはできません。ほかの人の印を消す書き込みは通ります（項目が消えたときに片付けるため）。消されても、認めた本人の端末は自分の記録を持っているので使い続け、次の同期で印を書き戻します。印が無い状態で始める別の端末だけが、もう一度承認を求めます。
- 閲覧のみのメンバーは書き込めないので、承認はその端末だけに残ります。
- この端末でどれが承認待ちかは `workspaces/<ハッシュ>/members.json` に持ちます（リセットでは消しません。メモがリセットのあとも残るためです）。このファイルが読めないときは、何も渡さずにエラーにします。
  - 承認待ちの印は、内容を取り込む前に書きます。途中で止まっても、印の無いままほかのメンバーの内容だけが入ることはありません。
  - 承認待ちの印も、承認した印も、その項目が消えたあとまで残します。「1つ前に戻す」で消す前に戻したとき、承認待ちだったものは承認待ちのまま、承認してあったものは承認済みのままです（別のアカウントがサインインしていれば、どちらもそのアカウントの承認待ちです）。印が3,000件を超えたときに捨てるのは、もう無くて「1つ前に戻す」でも戻らない項目の印だけです。いまある項目と戻せる項目の印は、件数にかかわらず捨てません。内容を取り込む前には何も捨てずに書き、取り込みが済んでから減らします。
  - ほかのメンバーが項目の内容を書き換えたときは、この端末が前の内容について持っていた根拠を引き継ぎません（「自分で見つけた」扱いにしません）。
  - AIが提案した文は、項目のときも「もう提案しない文」になったあとも同じ印で扱います。承認していない文を自分で消しても、自分のAIには渡りません。
  - 自動の項目の印は、種類と値（AIが提案した文は、その文そのもの）から作ります。一緒に送られてきた文面は使わないので、文面だけを差し替えて承認済みに見せることはできません。
  - この記録は、どのアカウントのものかを持ちます。同じ端末に別のアカウントでサインインすると、前のアカウントの承認は使いません。受け取ってあったメンバーの内容は全部、新しいアカウントの承認待ちになります（「このアカウントと同期し直す」を押す前でも同じです。この端末にしか無かった内容は、そのまま自分のものです）。
  - ほかの端末から来た手書きの行のうち、メモから読み直すと別の行になるもの（行末に空白がある、空白だけ）は取り込みません。種類の書き方が食い違う項目（手書きの行なのに「AIが提案した文」と名乗る、など）も読みません。どちらもサーバーには残します。
  - このファイルが無いのに、すでにメンバーの内容を受け取っている場合（この記録を持たない版で同期していた場合）は、受け取ってある内容の全部を承認待ちとして扱います。アカウントの印があるものと、この端末が自分で見つけた項目は除きます。
- 承認と「使わない」は台帳に `member-approve`・`member-decline`（actor は `approval`）として残します。この行はその端末にだけ残し、ほかのメンバーには送りません。

## プライバシーと制約

- 集計は端末の中で行います。外部へ出るのは、本人が行う通常のAI依頼に添える上記の内容と、AI要約のために送る抜粋だけです。どちらも送り先は本人が使っているAIで、新しい送信先はありません。AI要約をオフにすれば、見直しのために外部のAIを呼ぶことはありません。
- Pro のアカウントでサインインしていて「アカウントで同期する（Pro）」がオン（既定）のとき、自分用のメモ、一部のアプリ設定を本人の置き場に、共有ワークスペースの書き方をそのワークスペースの置き場に保存します（上の「アカウントでの同期」）。共有ワークスペースの書き方は、Pro のメンバー全員が読みます。共有していないワークスペースで学んだ内容と教材の本文は送りません。
- AI要約の項目は、AIが書いた文です。定型文ではないので、本人の文章の言い回しが短く入る可能性があります（14字以上の引用は採りません）。
- 共有していないワークスペースの中で個別に共有した教材、共有の同期で入った変更、バックアップの復元、時刻だけの変更、失敗した保存、オフの間の編集は対象外です。共有ワークスペースの教材は、下の「共有ワークスペースの書き方」のとおり読みます。教材を共有・移動・削除すると、その教材の実例とAI案の記録を次の読み取りで消します。
- この機能を入れる前に採用したAI案は区別できません。その文章は本人の文章として数えます。AI案の記録は3,000ブロックまでです。超えた分は古いものから消えますが、印を失った教材は、それ以降は本人の文章として読みません（AIの文章を本人のものとして数えないためです）。
- 語尾の読み取りは日本語の教材を前提にしています。英語だけの教材からは、TeXと構成の項目だけを読み取ります。
- 却下の理由、図形、コメントスレッドからは学びません。
- 以前の方式で作った自動要約は引き継ぎません。本人が手で直していた場合だけ、その行を本人の項目として残します。
