# PDF の取り込み

「ファイル > PowerPoint・PDFをインポート」で PDF を選ぶと、各ページの見た目をそのまま保った
新しい教材になる。数百ページの PDF を想定している (200 ページの合成 PDF で約 2 秒、
文字の多い実教材 116 ページで約 10 秒、スキャン 227 ページで約 45 秒)。

## できあがる教材

PowerPoint 取り込みと同じ **ページ固定** の教材 (`metadata.source.layoutMode: "fixedOverlay"`)。
本文は空の段落 1 つだけで、各ページはページ絶対座標の図形で描く。本文の流し込みでページは動かない。

| PDF の中身 | 教材での形 |
| --- | --- |
| 文字 | 編集できるテキスト図形。書体・大きさ・色・向きが同じで、同じベースラインに続く文字を 1 つにまとめる |
| 線・塗り・画像 | ページごとに 1 枚の SVG 画像 (背景レイヤー、ロック済み) |
| スキャンしたページ | ページ画像そのもの (文字認識はしない) |

- 用紙は、最も多いページ寸法にする (SigmaDoc の用紙は 1 種類)。用紙からはみ出すページは、背景と文字を同じ倍率で縮めて左上に揃える。
- 文字は同梱書体 (ゴシックは M PLUS 1p、明朝は Noto Serif JP) で描く。PDF の書体名から
  明朝・ゴシック・等幅と太字・斜体を判定する。書体の違いで幅が変わる分は、図形の横倍率
  (`textScaleX`) で PDF の幅に合わせ、折り返さない (`textWrap: "none"`)。
- ベースラインの位置は、行高 1 の行で書体の ascent / descent から求める。
- 画像は描画先の約 200dpi までに縮め、色数の少ない図は PNG、写真やスキャンは WebP にする。
  SVG は base64 にせず URL 符号化で埋め込む (二重の base64 で 4/3 倍にしないため)。

## 処理の分担

```text
主プロセス electron/pdf-import.ts
  pdf.js がページを描く → 記録用の 2D コンテキストが描画命令を受け取る
    ├─ 字形の塗り → 文字 (Unicode・原点・送り幅・大きさ・色・書体)
    └─ それ以外   → 塗り・線・クリップ・画像の記録 → ページの SVG
描画側 src/lib/pdf-import/
  抽出結果の形を検査 → 同梱書体で文字幅を測る → SigmaDoc を組み立てる
```

- 座標計算 (テキスト行列・フォーム XObject・クリップ) は pdf.js に任せる。記録用コンテキストは
  `CanvasRenderingContext2D` として振る舞うだけで、PDF の描画命令を自分で解釈しない。
  字形とふつうの塗りは、pdf.js が字形用に作る `Path2D` を覚えておいて見分ける。
- 記録できない描画 (パターン・グラデーション・合成モード・フィルター等) があるページは、
  文字を除いた描画を画像にして背景にする。記録用コンテキストで描けないページ (背景を読み戻す
  透明グループ等) は、文字を `getTextContent` から取り直し、残りを画像にする。
- 透明グループやソフトマスクの中の文字は pdf.js が別の画像面へ描くので、文字ではなく画像として残る。
- 1 ページずつ処理して解放し、ページごとにイベントループへ戻る。取り込みは同時に 1 件まで。

## 確認

- 単体: `src/lib/pdf-import/pdf-import.test.ts` (文字のまとめ方・SVG・文書の組み立て・スキーマ)
- 実アプリ: `tests/electron/pdf-import.spec.ts` (要 `pnpm run electron:prepare`)
  - 200 ページの合成 PDF を取り込み、150 ページ目の見出しのベースラインが PDF と 1.5px 以内、
    幅が 3% 以内であること、保存・再起動後も同じ図形数で最終ページまで描けることを確かめる。
  - 異なる用紙サイズを含む合成 PDF を取り込み、大きいページの端の文字と背景が所定の用紙に収まり、再起動後も同じ位置に描かれることを確かめる。
  - `SIGMA_PDF_IMPORT_FILE=/path/to.pdf SIGMA_PDF_IMPORT_PAGES=1,50` で実教材を取り込み、
    時間・容量を出して指定ページの画面を `test-results/` に残す。実教材はリポジトリに置かない。

## 既知の限界

- 教材の画像は SigmaDoc JSON に data URL で入る (アプリ共通の仕組み)。画像の多い PDF は教材が
  大きくなり (スキャン 227 ページで約 28MB)、保存のたびにその全体を書く。
- 縦書きの文字は 1 文字ずつの図形になる。数式は文字として取り込み、TeX には戻さない。
- 埋め込みフォントそのものは使わない。書体の見た目は同梱書体に置き換わる。
