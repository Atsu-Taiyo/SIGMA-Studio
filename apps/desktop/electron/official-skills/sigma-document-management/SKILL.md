# 教材・フォルダを作成・整理する

教材とフォルダの管理は、Sigma Studioの教材ライブラリの中だけで行う。OSのファイルやフォルダは触れず、パスも受け付けない。本文の編集は他の skill（sigma-body-authoring など）が担当する。

## 最初に

`list_local_documents` で、ワークスペース・フォルダ・教材の一覧と、それぞれのID・revision を取る。以降に使う `workspaceId` `folderId` `parentFolderId` `fileId` は、必ずこの一覧に出たIDだけ。名前から推測したIDを使わない。

## 操作

| したいこと | tool | 注意 |
| --- | --- | --- |
| 教材を作る | `create_local_document` | `workspaceId` が必須。`folderId` を省略するとルート直下。`title` を省略すると既定名。中身は空 |
| 教材名を変える・移動する | `update_local_document` | `title` か `folderId` の少なくとも一方。`expectedRevision` が必須。ルート直下へ戻すなら `folderId` を null |
| 教材を消す | `delete_local_document` | **ユーザーが削除を明示したときだけ。** 直前のrevisionを渡す |
| フォルダを作る | `create_local_folder` | `workspaceId` が必須。入れ子にするなら `parentFolderId` |
| フォルダ名を変える・移動する | `update_local_folder` | `name` か `parentFolderId` の少なくとも一方 |
| フォルダを消す | `delete_local_folder` | **ユーザーが削除を明示したときだけ。** 空のフォルダだけ消せる。中に教材や子フォルダがあると拒否される |

## 進め方

- 複数の教材をまとめて整理するときは、先に「何を・どこへ・どんな名前にするか」を短い一覧にして、そのまま実行してよい範囲かを判断する。名前の付け直しや移動は、ユーザーが頼んだ対象だけに限る。
- 削除は元に戻せない可能性がある。「整理して」「片付けて」だけの依頼では削除しない。削除する対象を挙げて確認を取る。ユーザーが対象と削除を明示している場合だけ実行する。
- 名前は、教材の内容が分かる短い名前にする。既存の命名規則（単元名、日付、学年など）が一覧にあれば揃える。
- 教材を作ったあとに中身も書いてほしいと頼まれたときは、その教材の `fileId` と最新のrevision（作成結果か `list_local_documents`）を使う。そのrunで書き込めなければ、無理をせず、作成した教材の名前と場所を報告して、開いて続きを頼んでもらう。

## 確認と報告

操作のあとに `list_local_documents` で結果を確認する。作ったもの・変えたもの・消したものを、名前と場所つきで短く報告する。実行しなかった操作（確認が要るもの、拒否されたもの）は分けて書く。
